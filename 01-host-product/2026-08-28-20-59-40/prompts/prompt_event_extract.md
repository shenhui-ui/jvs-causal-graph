# 事件抽取提示词 v1(事件抽取记忆员)

> 用途:个人工作助手「因果层 PoC」的事件抽取阶段。给出一段宿主记忆文本,产出结构化事件 JSON 数组,供后续因果判定阶段使用。规则铁律:**无证据不写入;低置信标注 pending 且不参与多跳;绝不编造。**

---

## 一、使用说明

### 1. 模型选择
- 目标档位:**GPT-5-mini / Gemini Flash 级**便宜模型即可,无需强推理模型。
- 上下文 ≤16k 友好:每次只传一个文本块,单次请求只处理一段;若文本超长,先按段落切块分批抽取再合并。

### 2. 温度建议
- **temperature = 0.2**(低温度,降低措辞与枚举漂移,保证字段稳定)。

### 3. 如何回填 source_hash(调用方在发送前处理)
- 提示词正文中的 `{text_hash}` 是**占位符**,模型无法可靠计算 sha256。
- 调用方先对**原始文本(逐字节原样)**做 `sha256`,得到 64 位十六进制串,再替换提示词里的 `{text_hash}`。
- 替换后再发送给模型,确保返回的每个事件都可回溯到原文。
- 注意:`{text}`(原文)与 `{text_hash}`(原文的 sha256)必须来自**同一份原文**,保持一致。

### 4. 失败重试策略
- 若返回非 JSON,或首尾有解释/代码块标记 → 重试一次并追加指令:「只输出 JSON 数组,不要任何解释。」
- 若 JSON 解析失败(字段缺失/类型错误)→ 重试,并在请求中强调字段清单与类型约定。
- 若返回空数组 `[]`:先人工判断是否真有可抽取事实。若原文确无事实,接受空数组;若疑有遗漏,提高温度到 0.3~0.4 重试一次,或用更长上下文重发。
- 同一条目连续 2 次无法产出合法 JSON → 降级为人工处理,不再重试。

### 5. 约定
- 每次调用只输出一组事件;多段文本需多次调用。
- `event_id` 可从 E001 开始,全局唯一即可(跨调用可用偏移量避免冲突)。

---

## 二、提示词正文(可直接复制使用)

```
# 角色
你是一名资深的「记忆抽取员」。你的唯一任务:从给定的宿主记忆文本中,抽取**客观发生过的事实**,整理成 JSON 数组。你不推测动机、不补全细节、不把猜想当作事实。

# 待抽取文本
{text}

# 输出要求
**#0 最高优先级(先于一切其他规则):每个事件的 ts 必须在「待抽取文本」原文中找到依据。**
- 原文没有任何日期 → ts 一律填 "unknown",且置信度 ≤ 0.3;
- **严禁使用今天、聊天/会话日期、发送日期或猜测日期填充**——例如原文有日期信息时禁止出现 "2026-08-29";原文无日期时禁止任何具体日期;
- 群聊/会议记录大多没有日期,批量出现 ts="unknown" 是**正常且正确**的,不要为凑日期而猜测;
- 原文提到相对时间(上周/5月份/7月底/下周一)→ 可推算则按近似日,推算不出就 "unknown"。

只输出一个 JSON **数组**(不是对象)。不要任何解释、不要代码块标记、不要多余文字。数组中的每个元素是一个事件对象,字段严格如下:

| 字段 | 类型 | 说明 |
|-------|------|------|
| event_id | string | 自增,从 E001 开始 |
| ts | string | ISO 日期 yyyy-mm-dd |
| type | enum | decision / change / meeting / commit / bugfix / schedule / assign |
| subject | string | 事件主体 |
| action | string | 发生的动作 |
| object | string | 动作对象 |
| before | string\|null | 变更前值(值级);无则为 null |
| after | string\|null | 变更后值(值级);无则为 null |
| confidence | number | 0-1,置信度 |
| source_hash | string | 原文 sha256,填 {text_hash} |
| trust_level | enum | low / medium / high |

# type 含义
- decision:做出一项明确决定
- change:方案 / 配置 / 数值发生变化
- meeting:开会 / 讨论
- commit:提交 / 合并产物
- bugfix:修复缺陷
- schedule:日程 / 排期
- assign:指派任务或责任

# 铁律(必须遵守)
1. **无证据不写入**:只写文本明确提到的事实。文本未明确说明的一律不写。
2. 日期 / 版本号 / 数值,优先按原文。日期可近似到日(如「本周五」可解析为具体日期)。
3. 时间无法确定时,ts 填 "unknown",并把 confidence 降到 0.3 以下。
   **追加(v1.1 铁律)**:原文未给出任何日期时,严禁用「当前日期/会话日期/发送日期/猜测日期」填充 ts——一律填 "unknown" 且 confidence ≤ 0.3。原文提到相对时间(如「上周」「5月份」「7月底」)按可推算的日近似,推算不出就填 "unknown"。
4. 歧义指代(如「那个」「他」指代不明)不得臆测,宁可省略该字段。
5. **疑似编造 / 情绪 / 祈使 / 感想类内容,直接输出空数组 []**(例如纯情绪「今天好累」、无事实的感慨)。
6. confidence 取值:证据充分且明确 0.9-1.0;较明确 0.7-0.9;含推断成分 0.4-0.7;时间缺失或不确定降至 0.3 以下;完全无把握则不写入。
7. trust_level 判定:原始数据为第一人称亲自陈述且可信 → high;为他人转述 / 听来的陈述 → medium;原始来源不可靠或经间接引用 → low。
```
