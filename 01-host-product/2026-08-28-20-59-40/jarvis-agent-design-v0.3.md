**只做一件事：时序-因果图谱 + 跨会话因果问答。**

## 1. 项目定位

### 1.1 贾维斯的本质

| 特征 | 含义 | 实现依赖 |
|---|---|---|
| **知情** | 比你还了解你自己 | 画像层 + 因果层 |
| **明理** | 理解事情**为什么**发生 | **因果层（自研核心）** |
| **常驻** | 不是你问它才动 | 宿主 heartbeat + 薄层 |
| **有授权** | 真能动手改东西 | 宿主 exec 审批 + 薄层 |
| **可托付** | 知道边界，敢说「这个我不建议」 | 人格层 + 治理薄层 |

相比 v0.1，新增「明理」一项。这是本次差异化的真正落点——**宿主在补「记住」，没人做「理解」。**

### 1.2 设计原则

1. **单点突破优先于全面铺开**
2. **复用优先于自研** — 宿主有机机制层一律复用，自研只做语义层
3. **可逆性优先于效率**
4. **用户可控优先于系统智能**
5. **因果必须可溯源** — 无证据不写入，置信度不足降级为事实陈述
6. **记忆是不可信输入** — 记忆是被污染的持久层，进 prompt 前必须隔离渲染

## 2. 生态调研

### 2.1 赛道现状

**OpenClaw 实测约 38.8 万 star**（2026-08，主语言 TypeScript，Node/Bun 运行）——远超 v0.1 记载的 14.5 万。衍生生态含 ZeroClaw、NanoClaw、IronClaw、moltis、Clawlet、SubZeroClaw 等数十个项目。

已解决：always-on 常驻、14+ 渠道接入、skills 系统、本地运行、语音 I/O、容器隔离。

### 2.2 宿主能力核实

#### 主动性 — heartbeat（机制层完善，语义层缺失）

| 能力 | 宿主实装 |
|---|---|
| 周期调度 | `heartbeat.every`（默认 `30m`，`0m` 禁用） |
| 活跃时段 | `activeHours`（含 `timezone`，窗口外跳过） |
| 投递目标 | `target`: `last`/`none`/渠道；`to`；`directPolicy` |
| 可见性 | `showOk`/`showAlerts`/`useIndicator`，按渠道、按账户覆盖 |
| 防洪 | flood protection、cooldown、busy 推迟 |
| 常驻意图 | scratch 文档（256 KiB，比较并交换，Agent 可自我更新） |
| 手动唤醒 | `openclaw system event --mode now` |
| 成本优化 | `lightContext` / `isolatedSession` / 低成本 `model` |
| 审计 | 底层会话记录保留 heartbeat 轮次，可审计/重放 |

**缺**：打扰预算（每日配额）、注意力调度、提醒类别体系。→ 薄层补。

#### 治理 — exec 审批（机制层完善，语义层缺失）

| 能力 | 宿主实装 |
|---|---|
| 权限模式 | `tools.exec.mode`: `deny`/`allowlist`/`ask`/`auto`/`full` |
| 询问策略 | `ask`: `off`/`on-miss`/`always`；`askFallback` |
| 白名单 | 按 agent，glob 路径 + `argPattern` 精确 argv |
| **防漂移** | 文件绑定——审批后执行前文件变更即拒绝 |
| **内联求值拦截** | `strictInlineEval` 捕获 `python -c`/`node -e` 等 |
| 审批完整性 | 存储规范 plan，事后篡改 command/cwd 即不匹配拒绝 |
| 生命周期 | `Exec finished` / `Exec denied` 事件 |
| 策略仲裁 | 取配置与主机审批中**更严格**者，审批只能收紧 |
| 预设 | `yolo` / `cautious` / `deny-all` |

**缺**：可逆性语义、权限四级制、操作级 registry。→ 薄层补。

#### 记忆 — 宿主正在补课，这是最大变量

宿主记忆**已不止两层**（2026-08-29 实测）：`USER.md`（画像层）+ `MEMORY.md`（长期层）+ `memory/YYYY-MM-DD.md`（工作层）+ `DREAMS.md` / `memory/.dreams/`（Dreaming 产物），另有 **memory-wiki 结构化层**（claims/evidence + 实体页 + 类型化关系边 + 矛盾/新鲜度看板，打包插件需 enable）与 **active-memory**（跨会话/时序深召回，成熟插件，文档自认 flat retrieval 在 temporal/multi-hop 上弱）。自动记忆冲刷（flush）**默认开**；Dreaming 三阶段后台晋升（含会话转录自动摄取、grounded backfill）在 **2026.7.1-2 起默认关闭**，需手动 enable（`plugins.entries.memory-core.config.dreaming.enabled=true`）【版本漂移修正：A03 报告「默认开」已过时，见 `docs\环境安装记录-20260829.md`】；issue #67970 已于 **2026-04-27 被关闭为「已实现」**（落地 v2026.4.24）。宿主记忆区现按周级节奏发布（2026-08 单月稳定版+多 beta）。

**判断**：宿主正在做的是**记忆的自动化写入、压缩晋升与半结构化**（存储/检索层），而本项目做的是**因果建模与反事实推理**（推理层）。自动晋升是压缩，因果建模是推理，两者不同层。

**但这也意味着差异化必须再往上一层——只做「记得住」已不够安全。这正是本次把核心升级为「因果」的直接原因。**（v0.3 精确表述：宿主已有实体关系边（`relationship-graph.md`）与「检索+recall 子智能体」形态，**缺的是「事件化因果边 + 图遍历/多跳因果问答 + 反事实」一等能力**——按 A03 预测表，该窗口约 3–6 个月。）

### 2.3 记忆层选型

| 方案 | 抽象模型 | 输出形态 | 存储 | 基准（厂商自评） | License |
|---|---|---|---|---|---|
| **memU** | 旧：Resource/Item/Category<br>新：Resource/RecallFile/RecallFileSegment | Markdown 文件系统 | in-memory / SQLite / Postgres | 新项目暂无 | Apache-2.0 |
| **Mem0** | 单层 + tag（**已引入 temporal reasoning**） | JSON | Qdrant / Postgres | 92.66% (LoCoMo) | Apache-2.0 |
| **Graphiti** | 时序节点 + 边（双时间轴） | 图查询结果 | FalkorDB / Neo4j | 94.8% (DMR)<br>LongMemEval 63.8% | Apache-2.0 |
| **Cognee** | Entity + Relation 图 | 图查询结果 | Neo4j / FalkorDB | ~85% | Apache-2.0 |

> 基准均为厂商自评，跨方案不可直接比较。

#### 2.3.1 memU 版本取舍（原「零适配成本」不成立）

**事实**：memU main 已按 ADR 0006/0007 重构——

| 维度 | 旧版（≈`357aefc8`） | 当前 main |
|---|---|---|
| 实体 | Resource / MemoryItem / MemoryCategory / CategoryItem | Resource / RecallFile / RecallFileSegment |
| 分类 | 六类：profile/event/knowledge/behavior/skill/tool | **track**（`memory`/`skill`；resource 固定 `workspace`；`line` 为 ADR 0007 提议、未落地） |
| Python | ≥3.13 + langchain-core | **≥3.11，移除 langchain-core** |
| 定位 | 24/7 主动记忆 Agent | Personal memory across agents |
| 拦截器 | before/after/on_error + insert_before/after | **无**（新版无工作流/拦截器；仅 `hosts/bridging/pipeline.py`，`AGENTS.md` 明确 embedding-only） |

**推荐：C 自研轻量层**（= Gate 1 决策 1）：memU **新版为底座**（文件化存储/向量/作用域/`memu-openclaw` 适配器）+ 自研轻量语义层（分类、LLM 抽取与路由、去重/纠错/精排）。理由：

1. 新版**移除 langchain-core、放宽到 Py3.11** — 依赖更干净，直接降低最大的工程风险（跨语言集成）
2. 六分类降级为 track 后，画像分类可自研薄层实现（见 §4.4），本就不复杂；为它锁死旧版不划算
3. pin 旧版 = 锁在更重的依赖上并放弃上游修复，长期是负债

**放弃项**：六分类带来的「LLM 知道往哪个槽塞」的低错误率优势，需靠自研分类 prompt 补偿。

**Plan B**：若 M0 集成 spike 证明替换成本 > 1 人月，转自研轻量记忆层（参考 Clawlet 的 SQLite + sqlite-vec 路线），仅复用宿主的文件化存储约定。

**适配成本**：memU 是 Python，宿主是 TypeScript。替换 = 常驻 Python 进程 + Python↔Node IPC/HTTP + 检索延迟预算 + 故障降级。**这是第一个真正的工程成本点，不是「零适配」。**

#### 2.3.2 选型结论

**memU（新版，存储与路由基座）+ Graphiti（时序骨架）+ 自研因果层（全部差异化）**

- memU 提供：Resource/RecallFile/RecallFileSegment 文件化存储（溯源锚点）、embedding 与 `ClientPool`、`user_id+agent_id` 作用域、`memu-openclaw` 适配器（可直接接入宿主记忆入口）
- **自研层需自建**（v0.3 修正）：LLM chat/vision/embedding 路由（新版 embedding-only，可借鉴旧版 `LLMProfilesConfig` 设计）与轻量钩子（新版无拦截器）
- Graphiti 提供：双时间轴（valid time / transaction time），因果推理的时序地基
- 自研因果层：唯一全新增量

**否决**：Mem0（分类弱于需求，且已非「无时序」但仍非因果）；全 Graphiti（架构重、图查询对 LLM 不友好）；Letta（需接受其 Agent 架构，与寄生策略冲突）。

### 2.4 差异化收敛

| 层 | v0.1 判断 | v0.2 判断 |
|---|---|---|
| 记忆·存储检索 | 空白 | 宿主正在补课，不再安全 |
| **记忆·因果推理** | 未识别 | **唯一真空白** |
| 主动性 | 空白 | 机制层已实装 80%，降为薄层 |
| 治理 | 空白 | 机制层已实装 90%，降为薄层 |
| 人格层 | 空白 | 低优先级，后置（此阶段仅人设文件，不做引擎） |

**差异化不在「能干多少活」，也不在「记得住多少」，在「是否理解事情为什么发生」。**

## 3. 总体架构

### 3.1 自研面（明确口径，删除「减少 60%」的无基准表述）

| 类别 | 内容 |
|---|---|
| **核心自研** | 因果层（因果边抽取 + 证据绑定 + 置信度 + 多跳展开 + 注入防御） |
| **薄层自研** | 主动性（四开关 + 配额 + 类别体系）、治理（可逆性命名 + registry） |
| **薄胶水** | 端侧降噪筛选、分层规划（战略/日程/单任务）、自研轻量分类层 |
| **复用** | 感知渠道、agent runtime、heartbeat 机制、exec 审批机制、云端强模型 |
| **后置** | 人格层（仅人设文件） |

### 3.2 接口抽象层（反寄生结构，新增）

宿主高频迭代且正在向记忆方向进化。为把「寄生」变为「依附可控」，定义四个端口，宿主作为可插拔实现：

```
MemoryPort      — put(resource) / recall(query, top_k) / correct(item_id, patch) / forget(item_id)
CausalPort      — link(cause, effect, evidence) / why(event) / counterfactual(event, intervention)
ProactivePort   — schedule(intent) / suppress(category) / quota() / emit(alert, level)
GovernancePort  — classify(op) -> reversibility / authorize(op) / audit(op)
```

**行为契约（最小集）**：

- `MemoryPort.recall` 必须返回带 `source_hash` 与 `trust_level` 的条目
- `CausalPort.why` 必须返回证据链，无证据时返回时序陈述而非因果断言
- `ProactivePort.emit` 必须遵守配额并可被 `suppress` 关闭
- `GovernancePort.classify` 对未知操作默认返回 `irreversible`

可插拔实现：OpenClaw（首选）/ ZeroClaw / moltis / 未来自研。

## 4. 核心自研：时序-因果图谱

### 4.1 为什么必须是「因果」

- 纯时序图谱能答：「方案在 T2 从 A 改成了 B」
- 因果图谱能答：「方案改是因为 T1 那次评审暴露了风险」
- **反事实能答**：「如果当时没改会怎样」——这才是因果推理的标志，也是纯检索系统的天花板

宿主在补记忆自动化（写入、晋升、wiki），**没有在做因果建模**。这是窗口所在。

### 4.2 双层设计（铁律）

| 层 | 性质 | 保证 | 承载 |
|---|---|---|---|
| **事实层** | 观测 | 硬保证，错了可纠 | Graphiti 双时间轴 |
| **因果层** | 推断 | 带置信度，必须可溯源 | 自研，绑定 memU Resource 锚点 |

1. 每条因果边必须绑定 ≥1 个原始 Resource 作为证据
2. 无证据的因果**不写入**
3. 置信度不足时**降级为时序陈述**，绝不编造
4. 用户可标注纠正因果边——既是纠错入口，也是优化信号

### 4.3 写入与召回

**写入管线**（v0.3 修正：新版 memU 无拦截器，挂载点改为「宿主侧前置阶段 + memU `commit_results` 之前插入自研步骤」；如需钩子自建轻量装饰器/事件）：

```
原始输入 → 模态分流 → 【自研:轻量分类】→ 去重合并
   → 【自研:因果边抽取 + 证据绑定 + 置信度 + 来源可信度标记】
   → memU commit_results（embedding + 落库）
```

**召回管线**：

```
粗排 → 中排 → 精排 → 【自研:reranker】→ sufficiency check
   → 【自研:因果路径展开】（沿因果边多跳，受来源可信度约束）
```

**分层淘汰**：`event` 与低置信度因果边快速衰减；画像、技能、高置信度因果边长期保留。

### 4.4 自研轻量分类层（替代失效的 memU 六分类）

新版 memU 分类降级为 track/line，需自研薄层补上：

| 类型 | 内容 |
|---|---|
| `profile` | 用户身份与稳定属性 |
| `behavior` | 行为模式与习惯 |
| `skill` | 技能与经验 |
| `event` | 发生的事 |
| `relation` | 实体间关系（供因果层消费） |

画像层复用此分类，**不自研引擎**，仅做消费侧整合。缺了它，「比你还了解你自己」只剩一半。

### 4.5 纠错：显式 + 隐式（新增）

- **显式**：用户直接改。纠错动作本身进事件流，可审计、可回滚（证据链：谁在何时纠正了什么）
- **隐式**（新增，第二层防线）：写入时对 `profile`/`behavior` 类做与既有记忆的矛盾检查，命中则**降级为「待确认」而非直接覆盖**。长期运行的大部分错误是隐式的（用户后续行为与已存记忆矛盾），没有这一层，「自信地记错」会持续放大

### 4.6 记忆注入防御（新增，因果层的特殊风险）

**记忆是被污染的持久层**：某次对话的恶意内容被抽取成记忆后，每次召回都是注入载体；**而因果层的多跳展开会将污染沿因果边传播放大**——风险高于普通记忆检索。

三层防御：

1. **来源标记**：每个记忆项携带 `source_hash` + `trust_level`（原始数据来源与可信度）
2. **隔离渲染**：记忆内容进 prompt 前隔离渲染，不可信文本不得进入指令区
3. **可信度传播**：**低可信来源的因果边不参与多跳展开**（这是因果层特有约束，普通记忆检索不需要）

注入检测失败处置：默认**拒绝召回**该条目并告警，而非清洗后召回。

## 5. 薄层设计

### 5.1 主动性薄层

**宿主关系**：宿主内实现（heartbeat + cron），非独立 sidecar。降低架构复杂度与运维成本。

**事件源清单**：
- 文件变更 → 端侧 OS watch
- 日历/邮件 → 优先宿主渠道，不足时直连 CalDAV/IMAP
- 阈值触发 → heartbeat scratch 检查清单
- 后台任务完成 → 唤醒 heartbeat

**（1）四开关** — 映射到宿主可见性配置：

| 开关 | 宿主机制 |
|---|---|
| 静默 | `showOk/Alerts/Indicator` 全 false（宿主直接跳过运行，省 API） |
| 仅指示器 | `showAlerts: false, useIndicator: true` |
| 标准 | `showOk: false, showAlerts: true, useIndicator: true`（宿主默认） |
| 全开 | `showOk: true` |

> **注**（v0.3 增）：上表映射基于宿主配置可见性（`showOk/showAlerts/useIndicator`），有效性需 **M0 实测验证**，宿主语义以实测为准。

**（2）每日配额** — 宿主无此概念，自研：

- scratch 文档维护当日已触达计数，Agent 通过 `heartbeat_respond` 的 `scratch` 参数自我更新
- 默认每日主动触达 ≤ 3 次；高优先级（日程冲突）可突破，低优先级严格受限
- 每条提醒附「关闭此类提醒」入口

**（3）提醒类别体系** — M0 定义，与自研轻量分类对齐：`deadline` / `conflict` / `followup` / `insight` / `checkin`

**（4）v1 打分特征**（规则 + 轻量评分，不上模型）：时效性、历史采纳率、行动必要性、可延迟性。被忽略 → 降权。

**成本**：heartbeat 每次运行完整 agent 轮次。用 `isolatedSession: true` + `lightContext: true`（100K → 2-5K token）+ 低成本模型。

### 5.2 治理薄层

**不自研权限引擎**，复用 `tools.exec.mode` / `security` / `ask` / allowlist / 防漂移 / 审计事件。

**自研：可逆性命名 + `reversibility registry`**

```json
{
  "op_id": "op_20260829_001",
  "origin": "proactive/brief",
  "tool": "file.write",
  "params_hash": "sha256:...",
  "reversibility": "reversible | partial | irreversible",
  "undo_payload": "backup_path 或具体逆操作",
  "auth_level": "L0 只读 | L1 建议 | L2 需确认 | L3 自主",
  "ttl": "7d"
}
```

映射规则：

| 可逆性 | 语义 | 映射到宿主 | 徽标 |
|---|---|---|---|
| `reversible` | 可撤销（建草稿、本地整理、加标签） | `allowlist` + `autoAllowSkills` | 绿 |
| `partial` | 撤销有成本（提交代码、移动文件） | `ask: on-miss` | 黄 |
| `irreversible` | 不可撤销（外发邮件、删除、支付） | `ask: always` + `askFallback: deny` | 红 |

`GovernancePort.classify` 对未知操作默认 `irreversible`。

**复用宿主纵深防御**：`strictInlineEval`、文件绑定防漂移、审批 plan 存储复用、策略取更严格者。

**合规注意**：宿主自带 secrets 机制，「凭据注入」设计前需先核对兼容性，避免两层凭据管理打架。

## 7. 数据红线与端云分工（新增，闭环 v0.1 缺口）

### 7.1 抽取模型位置（v0.1 未定义，核心权衡）

**矛盾**：红线承诺「原始个人数据不出端」，但记忆质量取决于抽取质量，而高质量抽取需要强模型。

**决策：分层抽取，按敏感度路由**

| 内容敏感度 | 抽取位置 | 说明 |
|---|---|---|
| 高（私人沟通、健康、财务） | **端侧** | 接受质量折扣，优先保证红线 |
| 中（工作文档、会议记录） | 端侧小模型初抽 + 云端精修摘要 | 只传初抽结果，不传原文 |
| 低（公开资料、技术文档） | 云端 | 无红线约束 |

**承认的代价**：高敏感内容抽取质量低于云端方案，而它恰恰可能是用户最希望被记住的。这是本方案的核心权衡，不回避。

### 7.2 「必要摘要」形式化定义

上云内容**仅含结构化元组，不含原文复述**：

```
允许：实体、关系、事件元组、时间戳、类型标签
禁止：原文片段、引述、可直接还原原文的复述
处理：最小化 + 脱敏（人名/账号/金额按需脱敏）
```

形式化后可验收：抽检上云 payload，检查是否含原文子串。

### 7.3 合规

- PIPL 个人信息处理与出境规则
- IM 数据授权范围（微信/企微几乎无官方开放接口，第一版不依赖）
- 端侧数据的用户导出与彻底删除能力

## 8. 演进路线与里程碑

### 8.1 里程碑与周期估算

| 里程碑 | 内容 | 估算 | 关键判据 |
|---|---|---|---|
| **M0** | 技术预研：memU↔宿主集成 spike、基线对比、QA 集、成本模型 | **2–4 周** | 集成成本 ≤1 人月，否则转 Plan B |
| **M1** | 跨会话因果问答打通（生死点） | 4–6 周 | 见 §8.2 三级验收 |
| **M2** | 沟通自动落库 + 去重/隐式纠错 + 画像整合 | 4 周 | 错误记忆基准集回归通过 |
| **M3** | 晨间简报 + 主动性薄层 | 3–4 周 | 提醒采纳率、15 日留存 |
| **M4** | 治理薄层 + 授权域自主执行 | 4 周 | 无不可逆事故 |

假设 2–3 人团队。单人执行则周期约 1.8 倍。

### 8.2 M1 三级验收

| 级别 | 问题 | 能力标志 |
|---|---|---|
| 基础 | 「那方案后来改了什么？」 | 时序检索——宿主原生能力可能已够用 |
| **差异化** | 「那方案**为什么**改了？」 | **因果推理——立身之本** |
| **终极** | 「如果当时没改，会怎样？」 | **反事实推理——纯检索系统答不了** |

**答不到第二级，说明因果层没做对，不应推进后续阶段。**

**关键**：M0 必须先做基线对比——验证宿主原生记忆（自动刷新/Dreaming/wiki）是否已能答第一级。若能，说明第一级无差异化，直接以第二级为门槛。

### 8.3 量化指标

| 维度 | 指标 |
|---|---|
| 跨时间线 QA | 评测集 ≥50 条（含因果更新题）；命中率 |
| 记忆质量 | top-k 召回命中率、错误记忆率、纠错率、重复率 |
| 主动性 | 提醒采纳率、忽略率、15 日留存 |
| 因果质量 | 因果边准确率（人工抽检）、反事实题通过率 |

### 8.4 止损线

- **M0 止损**：集成 spike > 1 人月 → 转 Plan B（自研轻量记忆层）
- **M0 止损**：基线对比显示宿主原生产物已能答第二级 → 差异化不成立，终止并回退
- **M1 止损**：因果准确率 < 60% → 暂停，回退到「时序 + 高亮相关事件」的弱方案
- **退出路径**：回退纯宿主方案的代价 = 已投入的 M0/M1 工时 + 数据模型迁移成本（MemoryPort 抽象层正是为降低此成本而设）
