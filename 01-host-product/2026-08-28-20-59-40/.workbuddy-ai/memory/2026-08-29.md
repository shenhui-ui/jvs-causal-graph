### 用户决策：接受架构收敛（选项 1）

### 宿主能力核实（查官方文档，决策依据）

**主动性 — heartbeat 机制层已实装 80%**：`every`、`activeHours`（含时区）、`target`/`directPolicy`、
`showOk`/`showAlerts`/`useIndicator`（按渠道按账户）、防洪与冷却、scratch 检查清单（Agent 可自更新）、
`system event --mode now`、底层会话记录可审计重放。
**缺**：打扰预算（每日配额）、注意力调度、提醒类别体系。

**治理 — exec 审批机制层已实装 90%**：`tools.exec.mode`（deny/allowlist/ask/auto/full）、
`security`/`ask`/`askFallback`、按 agent allowlist（glob + argPattern 精确 argv）、
**文件绑定防漂移**、**strictInlineEval 拦截 python -c/node -e**、审批 plan 存储复用、
`Exec finished`/`Exec denied` 事件、策略取更严格者、预设 yolo/cautious/deny-all。
**缺**：可逆性语义、权限四级制、操作级 registry。

结论：宿主有机制层，缺语义层/产品层 → 薄层的正确定义 = 复用机制层，自研语义层。

### 审核意见推翻的关键事实（重要，易复发）

   **我 v0.2 初稿依赖六分类做画像层，该论据失效，已改为自研轻量分类层。**

3. **OpenClaw 记忆是两层**（日日志 + MEMORY.md），已含自动刷新、Dreaming 晋升、wiki 层，
   官方自述 "still evolving"，issue #67970 正要求内置自动上下文抽取 —— **宿主正在补记忆层**。
4. "零适配成本"不成立：memU 是 Python，宿主是 TypeScript，跨语言集成是真成本。
5. Mem0 已引入 temporal reasoning，"平铺无时序"不再成立。
6. 基准数据（Graphiti 94.8%、Mem0 92.66%、Cognee ~85%）均为**厂商自评**，跨方案不可直接比。

### 我提出的三点修正（已纳入 v0.2）

1. **因果图谱不能吞掉用户画像** — 画像层改为自研轻量分类层（profile/behavior/skill/event/relation），
   不自研引擎，仅做消费侧整合
2. **因果层必须与事实层分离** — 事实层硬保证（Graphiti 双时间轴），因果层带置信度 + 必须绑定
   ≥1 个 Resource 作为证据；无证据不写入；置信度不足**降级为时序陈述，绝不编造**
3. **薄层 ≠ 不做** — 明确定义：复用机制层，自研语义层/策略层

### 额外识别的风险（审核意见未提，我的补充）

**因果层 + 提示注入 = 风险放大器**。记忆是被污染的持久层，而因果层做多跳展开会把污染沿因果边传播，
危害高于普通记忆检索。防御：来源可信度标记 + 进 prompt 前隔离渲染 +
**低可信来源的因果边不参与多跳展开**（因果层特有约束）。

### v0.2 关键设计

- **memU 版本取舍**：推荐跟随新版（依赖更干净，降低最大工程风险），放弃 pin 旧版；
  Plan B = 自研轻量层（Clawlet 的 SQLite+sqlite-vec 路线），触发条件集成成本 >1 人月
- **接口抽象层**（反寄生）：MemoryPort / CausalPort / ProactivePort / GovernancePort
- **数据红线闭环**：按敏感度分层路由（高敏感端侧抽、中敏感端侧初抽+云端精修、低敏感云端）；
  「必要摘要」形式化定义 = 仅结构化元组，不含原文复述，可抽检验收
- **M1 三级验收**：时序（宿主可能已够）→ 因果（立身之本）→ 反事实（纯检索做不到）
- **止损线**：M0 集成 >1 人月转 Plan B；M0 基线对比显示宿主已能答第二级则终止；
  M1 因果准确率 <60% 回退弱方案

### 清单三处修正

1. **`brew` 不适用于 Windows** — 那是 macOS 包管理器。Windows 路径应是 npm 全局安装或官方安装脚本
2. **Windows 原生可行但有限** — 有「Windows 原生安装（不使用 WSL）」路径（含从源码安装），
   并非完全不可行；但 OpenClaw 深度依赖系统进程管理与**文件监听**，原生环境会受限。
   用户「WSL2 最稳」的判断基本正确
3. **配置项名称需核对** — `enable memory-wiki / active-memory` 的写法需以
   `/reference/memory-config` 官方文档为准

### 重大发现：Active Memory Plugin（冲击 v0.2 设计）

**Active Memory Plugin 是 OpenClaw v2026.4.10 引入的真实功能**：
它是一个在**主 Agent 回复之前自动运行的记忆子 Agent**，自动搜索并注入相关上下文。
另有 `memory-wiki` 与 `memory.search.rememberAcrossConversations` 配置。

**影响**：
- v0.2 设计的召回管线（粗排→中排→精排→reranker→sufficiency check）在宿主已有产品化实现
  → **自研召回管线 = 正面重复，应从自研范围中移除**
- 宿主能力边界再次上调：不仅有自动刷新 / Dreaming 晋升 / wiki 层，还有**自动召回注入**
- 差异化进一步收窄，**只剩因果边建模 + 反事实推理 + 因果层注入防御**（宿主均无）

**已知坑**：社区反馈 Active Memory 配置不当会「卡死」，寄生时需注意。

### PoC 顺序建议（重要）

先装宿主并开启原生记忆（含 Active Memory + memory-wiki），
