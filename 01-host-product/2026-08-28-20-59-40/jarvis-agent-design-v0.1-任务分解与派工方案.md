# 《贾维斯个人 Agent》项目任务分解与派工方案 v1.0

> 依据:`jarvis-agent-design-v0.1.md`(原方案)+ `jarvis-agent-design-v0.1-审核意见.md`(2026-08-29 审核)
> 用途:把「修订一版 + M0 技术预研」拆成可独立派工的工作项(WP),每条含任务书要素,可直接派给团队成员或 AI 子代理。
> 派工原则:**决策类任务(决定方向)不外包,只做人机参谋;执行类任务全部可并行甩出;时间敏感的事实核查优先派。**

---

## 一、总览:七波派工图

```
第0波 立项准备(0.5天)─ D01 你本人定范围/人力/红线 ──────────────┐
第1波 事实与决策支撑(并行 4 项)                                    │
   A01 生态快照复检  A02 memU新旧版对比  A03 宿主记忆现状  A04 空白再确认
        └──────────────┤                      │
第2波 你拍板(Gate 1)  D01' memU 版本取舍 + M0 范围 + 停工条件 ───┼ 全部后续的前置
第3波 v0.2 修订(并行 5 项)A05~A09 ──→ A10 统稿(串行收口)         │
第4波 设计与接口(并行 5 项,D02~D05/F02 部分)                    │
第5波 M0 技术预研(核心,串行两条链)                              │
   链A:D05 接口摘要 → B01 集成spike → B02 基线对比实验            │
   链B:C01/B02 数据准备 → B03 成本 → B04 端侧环境 → B05 导入隐私   │
第6波 项目管理(并行 3 项)F01~F03                                 │
第7波 Gate 2 评审(G01 你主持)─ 决策:放行M1 / 调整 / 终止        │
```

**关键路径**:D01'(拍板)→ D05 → B01 → B02 → G01。其余全部可并行。
**总估算**:约 38 人日;2~3 人团队并行,3~4 周可达 Gate 2(与审核意见「M0 预研 2–4 周」一致)。

## 三、任务书(每条可直接复制派发)

### 第 1 波:事实与决策支撑(4 项并行,全部可交给 AI)

**A01 生态快照复检**
- 背景:原方案与审核意见基于 2026-08-29 前的快照,star 数已明显过时(如 OpenClaw 实测 38.8 万 vs 方案写的 14.5 万)。
- 目标:在派工当天,把方案与审核意见中所有「时效性数据」刷新为最新实测值。
- 范围:OpenClaw、memU、Graphiti、Mem0、ZeroClaw、IronClaw、Clawlet、rho 等 15 个项目的 star 数/最近 commit 时间/最新 release/license 变化。
- 不做:不评价,只采集。
- 交付物:`#docs/ecosystem-facts-20260829.md` 表格。
- 验收:每条数据带来源 URL 与查询时间;与旧值不同的条目用 Δ 标注。
- 估算:0.5 人日。
- **AI 接单提示词**:「用 web 搜索与 GitHub API 实测下列 15 个仓库的最新 star 数、最近提交日期、最新 release tag 与 license:openclaw/openclaw、NevaMind-AI/memU、getzep/graphiti、mem0ai/mem0、zeroclaw-labs/zeroclaw、nearai/ironclaw、mosaxiv/clawlet、mikeyobrien/rho、Virtual0ps/gaia、agentscope-ai/ReMe、memodb-io/memobase、cnfug/nanoclaw、genlayerlabs/subzeroclaw、moltis-org/moltis、machinae/awesome-claws。输出 Markdown 表格,每条注明来源 URL 和抓取时间。」

**A02 memU 新旧版对比研究**
- 背景:审核发现设计稿依据的是 memU 旧版(≈commit `357aefc8`:四实体+六分类+Py3.13+langchain-core),当前 main 已重构(Resource/RecallFile/RecallFileSegment、track/line、Py3.11+、移除 langchain-core、定位改「Personal memory across agents」)。这是全方案最关键的未决点。
- 目标:给出「pin 旧版 vs 跟随新版 vs 自研轻量(仅借用其文件化存储+路由)」三选一的对比与推荐。
- 范围:数据模型差异、写入/召回管线差异、拦截器机制、依赖与部署差异、license、社区活跃度(commits/issue 响应/ADR 演进)、迁移风险、维护成本。
- 不做:不做代码级集成实验(那是 B01)。
- 交付物:`#docs/memu-新旧版-对比与推荐.md`(含推荐与理由、风险)。
- 验收:给出量化对比表(≥8 维度);推荐结论明确;注明每个事实的来源(commit/URL)。
- 估算:2 人日。
- **AI 接单提示词**:「对比 memU 旧版(commit 357aefc8 或 README/models.py 含四实体+六分类的版本)与当前 main 的差异:实体模型、记忆分类、写入/召回管线、声明式工作流与拦截器(before/after/on_error 与 insert_before/after)的语义、Python 版本与依赖(旧:3.13+langchain-core;新:3.11+无 langchain-core)、定位变化(24/7 主动记忆→Personal memory across agents)、存储后端、license、社区活跃度(近期 commits/issue/ADR)。输出 8 维度以上对比表 + 三选一推荐(旧版 pin / 跟随新版 / 自研轻量层只复用存储),给出推荐理由与放弃项,并注明事实来源。来源:NevaMind-AI/memU 仓库与 ADR、deepwiki、doramagic.ai 说明书。」

**A03 OpenClaw 记忆能力现状深挖**
- 背景:审核发现 OpenClaw 记忆区官方自述 "still evolving",已含自动记忆刷新、Dreaming 后台晋升、知识 wiki 层,且有 issue #67970 请求「自动上下文抽取+日日志写入」——宿主正在向本项目差异化方向进化,需摸清现状以评估「剩余空白」。
- 目标:回答「OpenClaw 内置记忆现在到底能做到哪一步」「项目差异化窗口还有多久」。
- 范围:官方 docs(记忆概念页)、changelog/releases 近 3 个月、issue #67970 进展、社区(awesome-claws/agents-radar)对记忆能力的讨论、Dreaming/wiki 的实际实现程度。
- 交付物:`#docs/openclaw-memory-现状报告.md`(能力清单 + 时间线 + 判断)。
- 验收:能力清单逐条标注「已实装/实验性/规划中」+ 来源;给出「3 个月内宿主可能补齐的能力」预测表。
- 估算:2 人日。
- **AI 接单提示词**:「调研 OpenClaw 记忆系统现状:读官方记忆文档(docs2.openclaw.ai/zh-CN/concepts/memory)、仓库 docs/concepts/memory.md、近期 CHANGELOG/releases、issue #67970 及其评论,以及社区(awesome-claws、agents-radar、官方 Discord/论坛)对记忆能力的讨论。输出:①当前已实装能力清单(自动记忆刷新、Dreaming 后台晋升、wiki 层、会话记忆等,逐项标注已实装/实验性/规划中+来源URL);②近 3 个月记忆相关变更时间线;③预测表:哪些记忆能力 3 个月内可能被补上;④结论:目前「结构化记忆+时序」是否仍是空白。」

**A04 生态空白再确认**
- 背景:方案核心差异化是「注意力调度/打扰预算」与「权限四级+可逆性判定」,审核仅抽查未见竞品。
- 目标:较高置信度确认这两块仍是空白(或找出隐藏竞品)。
- 范围:搜索 OpenClaw 生态 20+ 项目与通用 agent 项目(含 2026 年新项目),关键词:interruption budget、attention scheduling、proactive agent 打扰控制、reversibility/undo permission、audit permission levels。
- 交付物:`#docs/生态空白再确认.md`(覆盖表 + 各项目一句话说明 + 判断)。
- 验收:每个「空白」给出搜索方法与覆盖范围;发现近似竞品则单独小节。
- 估算:1.5 人日。
- **AI 接单提示词**:「验证两个观点:①「注意力调度与打扰预算」是否无人做;②「权限分级+可逆性判定(可撤销才可自主执行)+全量审计」是否无人做。检索 OpenClaw 生态(awesome-claws 清单)及泛 agent 生态中 2025–2026 年的项目,重点看 rho、gaia、IronClaw、ZeroClaw、SubZeroClaw、moltis、Clawlet、OpenClaw 本体及知名框架的文档与 README。输出:覆盖表(项目×能力:注意力调度/打扰预算/权限分级/可逆性判定/审计),每个能力标注谁做了或确认无人做,给出证据 URL;如有近似竞品,单独小节描述其实现。」

### 第 4 波:设计与接口(5 项并行)

**D05 接口抽象层定义(2 人日,技术成员)**
- 范围:定义 MemoryPort(读写/召回/纠错/审计)、ProactivePort(事件订阅/候选提醒/配额)、GovernancePort(授权查询/可逆性查询/审计上报)的接口签名(TypeScript 为主,标注 Python 对应物——spike 两端都要用);给出「宿主适配器」接口(OpenClawAdapter/ZeroClawAdapter/moltisAdapter 的差量说明)。
- 不做:不实现具体适配器(B01 中只做 OpenClaw 一个)。
- 验收:接口文档可直接指导 B01 编码;三个 Port 的职责与「生态替换成本」一节对应。
- 前置:读 D01 纪要。

**D02 记忆层设计 v0.2(3 人日)**
- 范围:按 D01 选定的 memU 路线设计:数据模型(含版本标注)、写入管线(原始输入→降噪→类型分流→并发抽取→去重/冲突检测→持久化)、显式+隐式纠错(行为否决、证据链、降级为「待确认」)、去重策略(阈值/时间窗/类型)、分层淘汰(各类型衰减策略)、读取管线(三级召回+精排+sufficiency check)。
- 交付物:`#docs/design-memory-v0.2.md`。
- 验收:每条机制有「失败场景→行为」表;与 C02 基准集类型对应。

**D03 主动性引擎设计 v0.1(2.5 人日)**
- 范围:宿主关系结论(宿主内 skill vs sidecar,给对比与推荐);事件源清单(文件 watch/日历 CalDAV/邮件 IMAP/阈值)与各源接入方式;注意力打分 v1 特征(时效性/历史采纳/行动必要性/可延迟性)+反馈闭环(忽略→降权);打扰预算模型(≤3 次/日、高优先级突破、免打扰时段、一键关闭)与提醒类别体系(建议与记忆分类对齐)。
- 交付物:`#docs/design-proactive-v0.1.md`。
- 验收:能回答「某条提醒为什么今天发/没发」;配额规则可用伪代码表达。

**D04 治理层设计 v0.1(3 人日,安全向成员)**
- 范围:权限四级与授权的细化(授权域定义:路径/资源/时间窗);reversibility registry 完整 schema(op_id/tool/params_hash/reversibility 三态/undo_payload/ttl,JSON Schema + SQL 建表);审计事件模型;记忆注入防御(来源标记:原始数据 hash+可信度;记忆内容隔离渲染:不可信文本不进指令区;注入检测的失败处置:拒绝 vs 清洗);与 OpenClaw secrets 机制的兼容方案。
- 交付物:`#docs/design-governance-v0.1.md` + `schemas/reversibility.schema.json`。
