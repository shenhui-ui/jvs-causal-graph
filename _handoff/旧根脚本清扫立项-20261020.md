1. **迁移事实**（2026-09-16，`MIGRATION-RECORD.md`）：4 个目录真实字节迁入 `Desktop\JVS\`，原路径留 Junction（顶层 3 个 + `outputs` 子项 22 个；`MIGRATION-RECORD` §2 记「24 个」，PENDING §四 记「25 个」——**口径差异，执行时须现测**）。48,424 处硬编码绝对路径因此继续解析，迁移当日**零代码改动**。
2. **现状已变**（2026-09-21 实测，PENDING §四）：OS 已把 `host-workspace` 下**全部 junction** 判为「**不受信任的装入点**」（`WinError 448`；重解析标签 `0xA0000003` = 真 Junction；长路径前缀不可绕过；bash→python 与 PowerShell 两条独立路径一致；目标侧真实路径可读）。
   ⇒ **旧根在原生 Windows 进程下已完全失效**，不再只是「校验器拒绝追随」。
3. **直接后果（已发生）**：5 个冻结索引 1,165 条 `payload_path` 全不可解析 ⇒ scoped 复核不可端到端复现。**该项已由 R2=③ 裁定「仅登记不改」**，属已接受的已知限制，**不在本立项范围**。

   - 新会话按文档跑历史脚本 ⇒ 失败原因不明（像"环境坏了"而非"路径失效"）；
   - 门禁/回归若引用旧根 ⇒ 校验在克隆副本或新机上静默失效；

## 4. 三条路线（供项目方裁定）

### 路线 A：批量改写 + 门禁守卫

- **写集**：S1 + S2（`.py` 345 + `.sh` 3 的量级；S3/S4 不动）
- **方法**：25 个 junction 的 src→dst 映射（`MIGRATION-RECORD` §2 + 现测 `os.path.islink`/`realpath`）；**纯前缀替换**，不解析、不重排、不改逻辑
- **优点**：路径复原、历史脚本可重跑、"可复现"承诺落地
- **缺点**：写集大、爆炸半径大（数百文件）、需逐批回归；每批都要过 py_compile + 抽样回读
- **风险控制**：按目录分批（**≤3,000 文件/命令**，环境铁律 2）；每批四步：改 → 逐文件回读 → `py_compile` → commit；跑全量门禁

### 路线 B：豁免文档化

- **写集**：仅新增 `_handoff/OLD-ROOT-EXEMPTION.md`
- **内容**：逐件登记「依赖旧根 / 现状（不可运行）/ 重建 junction 的前置 / 判定命令」；并写明「**这不是"没问题"，是"已知不可运行"**」
- **优点**：零改动、零风险、半天可完成
- **缺点**：**345+ 脚本保持不可运行**；"可复现"降级为静态核对；后续任何重跑需求都要先做路线 A

### 路线 A-lite（折中）

- **写集**：仅 **S1 活件**（门禁/回归/生成器直接引用的少数脚本）+ 路线 B 的豁免登记
- **优点**：风险最小、收益集中在「门禁与回归不被旧根拖死」
- **缺点**：S2 历史脚本仍不可重跑（但已显式登记，不再"静默坏"）
- **推荐说明**：本文**不作推荐结论**（红线 7）；仅指出：若本轮只想消除"静默坏"，A-lite + B 可当日收口；若要恢复历史脚本重跑能力，必须 A。

## 6. 门禁守卫设计（路线 A / A-lite 的必需件）

**目标**：防**新增**旧根引用进入主线，而非追究历史存量。

- **判据口径**：`git-gate.sh` 新增一步，扫 **本分支相对 `main` 的新增/修改行**（`git diff main...HEAD -U0`），命中 `host-workspace` 的**路径形状**（`host-workspace\` / `host-workspace/`）⇒ **FAIL**
- **白名单**：S3/S4 类的既有文件**不参与**（diff 口径天然排除未改动文件；若某留痕文档被改，其旧根引用须在 `exemptions` 列表显式登记）
- **⚠️ 反例（必须避免）**：**不得**用全库 `grep -r "host-workspace"` 作判据 —— PENDING §四 / MIGRATION-RECORD / 评审报告等 324+ 处**合法历史引用**会立刻假红
- **负向自证**：夹具①新增行含旧根 ⇒ FAIL；②未改动的留痕文件含旧根 ⇒ PASS；③白名单登记后 ⇒ PASS；④清单为空 ⇒ FAIL（反假绿，沿用 `REG_TESTS` 同款守卫）
