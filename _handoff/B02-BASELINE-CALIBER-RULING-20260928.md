## 2. 裁定依据（5 条，逐条可核）

### 依据 1 —— 定义优先：B02' 的定义**已经写明**基线臂是宿主原生

- `docs/Gate1-决策材料包.md` **第 49 行**（逐字）：
  > **链 B 基线对比**：B02' **宿主原生 vs 宿主+因果层**｜用 C01 40 条 QA：① 宿主原生(active-memory/wiki/Logbook) ② 宿主+自研因果层；出 top-k 命中/因果题正确率对比 —— **这是 Gate 2 的核心裁决材料**
- `docs/M1-立项书-v0.4.md` **第 8 行**（逐字）：「B02' = **宿主原生 vs 宿主+因果层**基线对比」。
- ⇒ 这不是「二选一的口味问题」，而是**定义已明文**的问题。除非走正式变更程序，口径应服从原始定义。

### 依据 2 —— 目的论：换成骨架管线，B02' 就答不了它该答的问题

- B02' 是 **Gate 2 的核心裁决材料**，其唯一目的是度量**自研因果层相对宿主既有记忆能力的增量价值**。
- 这正是 Gate 1 决策 2 的立项前提（差异化 = 宿主之上的「因果图谱问答」，主动/治理降为薄层）。
- 若基线 = 我方骨架管线，B02' 退化为「**我方管线旧版 vs 新版**」的自比 ⇒ 回答的是「这版比上版好多少」，
  **无法回答「因果层是否值得做」** ⇒ 不构成 Gate 2 的裁决材料。

### 依据 3 —— 可比性：骨架管线基线**连基本可比性都不满足**（红线 18）

- 立项书 v0.6 第 37 行要求口径 =「**同题集 / 同判分器 / 去标记盲评**」。
- 09-02 骨架基线（6/30 = 20.0%）用的是 **`tools/eval/eval_m1.py` 规则启发式（rule_heuristic）**；
  当前主验收用的是 **`tools/causal/llm_judge.py` LLM 三要素** ⇒ **判分器不同轴**。
- ⇒ 按红线 18「**不同轴 ⇒ 标定/差值本身无效**」，**不得给差值** ⇒ 骨架管线**不能**充当可比基线。

### 依据 4 —— 实测：缺口是「缺臂」，不是「口径不明」

| 核验 | 命令要点 | 结果 |
|---|---|---|
| ① 「宿主原生」的回答产物 | 全库 `grep -rl "宿主原生"` | **无任何回答产物** —— 仅命中定义文档（Gate1 / 立项书 v0.1–v0.5 / M0执行方案）与 PM 文档（PENDING / status_map / 功能表） |
| ② 名为 `*baseline*` 的产物是什么 | 读 `host_memory_dump/m1_10_baseline_final/answers.jsonl` 首条 `answer_text` | `cause(strong): … 理由:R60059…` ⇒ **全部是我方因果链输出**，不是宿主原生 |
| ③ 项目实际叫「基线」的产物 | `M1-10-正式基线报告-20260902.md` | = **定版图库 · 骨架管线 6/30 = 20.0%**，判分器 = `eval_m1.py` rule_heuristic |

- ⇒ 项目**从未跑过**宿主原生臂。**这恰恰是必须补跑的缺口**，而不是「改用现成产物」的理由。

### 依据 5 —— 反向警示：骨架口径会产出一个「好看但无效」的结论

- 若按骨架管线口径：差值 = 21 − 6 = **+15 题** ⇒ 落 **R4（> +4.5）⇒ 放行 M2 立项**。
- 该结论**不得**被引用为 Gate 3 结论 —— 判分器不同轴时两数之差**没有解释力**（红线 18，本项目已有同族教训）。

## 3. 两种口径差异对比

| 维度 | **宿主原生**（采用） | **我方骨架管线**（不采用） |
|---|---|---|
| 定义出处 | Gate1 第 49 行 / 立项书 v0.4 第 8 行 **逐字** | 项目实际产出「基线」（09-02） |
| 对照含义 | 因果层 vs 宿主既有记忆能力 = **增量价值** | 新管线 vs 旧管线 = **自身迭代** |
| 回答的问题 | 「因果层是否值得做」（Gate 2 前提） | 「这版比上版好多少」 |
| 判分器 | 须与主验收同轴（`llm_judge.py` LLM 三要素） | 现有 6/30 用 `eval_m1.py` rule_heuristic ⇒ **不同轴** |
| 现有产物 | ❌ **无**（缺臂，须补跑） | ✅ 有（6/30 = 20.0%），但**不可直接比** |
| 差值可用性 | 补齐 P1–P5 后可算 | **当前不可算**（红线 18） |
| 若强行使用 | — | 得 +15 题 ⇒ R4 放行 M2 ⇒ **无效，禁止引用** |
| 是否满足「同题集/同判分器/去标记盲评」 | 可满足（需补跑） | **不满足**（判分器不同轴） |

## 4. 适用条件与前提

> 本裁定在以下前提成立时**可执行**；前提不成立时转入 §5 的切换条件。

| # | 前提 | 现状 / 说明 |
|---|---|---|
| **P1** | **宿主原生臂必须可运行 / 可复现** —— 宿主记忆栈（active-memory / wiki / Logbook）能被以「回答同一题集」的形式调用并留档 | ⚠️ **本裁定的关键未知项**：全库无宿主原生评测产物 ⇒ 历史上从未跑通。**裁定后第一件事 = 做可行性确认**（不是裁定前的前置） |
| **P2** | **同题集** —— 与主验收同一题集（30 题；若用 C01 40 条 QA，须与主验收题集对齐并写明映射） | 可满足 |
| **P3** | **同判分器** —— 两臂均用**当前** `llm_judge.py`（LLM 三要素）；**不得**一臂用 rule_heuristic | 可满足（须重跑判分） |
| **P4** | **去标记盲评** —— 去来源标记 + 随机混序 + 判分方不知归属（单人执行以「判分方不知归属」为上限，留档复核） | 可满足 |
| **P5** | **同时间窗 / 漂移自证** —— 判分侧存在漂移风险（红线 25：同一模型名、同一输入，09-18 判 `true`、09-23 判 `false`）⇒ 两臂须在**同一批次**内判分，或先跑「**同输入重判**」自证 | 可满足（须同批） |

## 5. 切换条件（何时改用另一口径）

### 5.1 从「宿主原生」切到「我方骨架管线」—— 唯一合法条件（三条**须同时**满足）

1. **P1 可行性核验判定为「不可行」**：宿主原生臂经确认**不可运行 / 不可复现**（宿主栈无可用接口、
   无法复原当日宿主状态、或权限 / 成本不可行）⇒ 须出具**可行性核验记录**作为依据；
2. **消除判分器不同轴**：用**当前 LLM 判分器**重跑骨架管线臂（不得沿用 rule_heuristic 的 6/30）；
3. **正式变更口径**：报**评审会批准**（立项书 v0.6 第 26 行 / 第 183 行：「**确定性口径变更须评审会批准（§6）**」），
   并**同步修订立项书 / 验收表**，明确 B02' 语义已从「因果层 vs 宿主原生」改为「新管线 vs 骨架管线」，
   **并显式声明该口径不回答 Gate 1 决策 2 的立项前提**。

> ⚠️ 未走完 1–3 而直接给差值，属红线 18 违规（不同轴差值），不得写入 Gate 3 材料。

### 5.2 从「我方骨架管线」回切「宿主原生」

- 若已按骨架口径执行，而**宿主原生臂后来变得可运行** ⇒ **应切回宿主原生口径**（后者才对应原始定义），
  并按 §4 P2–P5 重跑，原骨架口径结果降为附注。

### 5.3 兜底：两臂皆不可得

- ⇒ **不得给差值**。按 `M1-15-Gate3-材料包-20260928.md` §6 出「**不可判定**」。
  ⚠️ **原写「Gate 3 维持阻塞（= 现状）」已过期** —— Gate 3 已于 2026-09-28 由项目方签署「放行」（§9），
  但**该放行未使用 B02' 差值** ⇒ 本条现为**放行后仍需补的口径缺口**，不再是关口阻塞项。
- ⚠️ 不得以「题数差无法算」为由，用骨架口径的 +15 题「代替」判定 —— 那是把无效结论当结论。
