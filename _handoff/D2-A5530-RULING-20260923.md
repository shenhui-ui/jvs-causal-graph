## 三、⭐⭐ 为什么原问是**伪二分**

`causal_graph.py` L120-131 现测：

```python
def _edge_expandable(edge):
    if edge.get("strength") in ("weak", "pending"):
        return False
    confidence = edge.get("confidence")
    ...
    return float(confidence) > 0.6        # ← 只有这里决定「能否继续多跳」
```

⇒ **能否展开 = `strength ∉ {weak,pending}` ∧ `confidence > 0.6`**（两条轴取合取）。

`A5530` 的 `confidence = 0.6` **恰在边界上** ⇒ **无论标 `strong` 还是 `weak`，`_edge_expandable` 都是 `False`**
⇒ **可达性、逐题证据链完全相同**。⇒ 原问「升 `strong` 还是降 `weak`」**问不到点上**：
它问的是**标签**，而决定行为的是**数值**。

**⇒ 真问题是**：**要不要人工把 `confidence` 抬到 `>0.6`？**

## 五、判据层核查（**中性事实**，不作语义裁决）

### 5.1 `A5530` 逐条对不上 v2.1 的 `strong` 三情形

`prompts/prompt_causal_edges_v2.1.md` L64-67（逐字），`strong` = **满足任一**：

| # | 情形 | `A5530` 现测 |
|---|---|---|
| 1 | 存在**明确因果/触发/替换句**（「因为 X 所以 Y」等） | ⚠️ 两端均为 `decision`，rationale 为**归纳式**表述，无跨端因果句 |
| 2 | **决策→变更衔接**：同 subject/主线上的 `decision` 与后续 **`change`**，时间先后、**对象一致** | ⚠️ to 端 `type = decision`（**不是 `change`**）；两端 `object` **不同**（`场景分类` vs `陶瓷场作业运动很慢视频`） |
| 3 | **变更差分明确**：`change` 事件的 after 自带 before→after 差分 | ⚠️ 两端 `before` **均为 `None`**，且均非 `change` |

⇒ **三情形逐条不满足**；而人工判读所给依据是「**规则→实例闭环**」
（`商业场景定义` 规则 → `陶瓷场作业` 实例判定）—— **该形态不在三情形列举内**。

> ⚠️ **这不等于判读错**：v2.1 写的是「满足任一」（**充分条件列举**），**未写「仅限」**。
> ⇒ 它属**未被 v2.1 覆盖的第四形态**，须项目方裁定是**承认该形态**还是**按现有三情形判**。
> ⛔ 本节只做「依据文字 × 三情形列举」的**覆盖性核对**，**不作**「该边是否成立」的语义裁决（红线 7）。

### 5.2 ⭐ `confidence` 是**模型自报数值**，v2.1 从未规定「`strong` ⇒ `conf > 0.6`」

- v2.1 里 **`strength` 由证据形态规则派生**（三情形 / weak 定义）；
- **`confidence` 是判边器自报的标量**，铁律 3 只规定「`>0.6` 才可入库」；
- ⇒ 两条**独立轴**。`cause/strong` + `conf=0.6` **在 v2.1 里并不自相矛盾**
  （「矛盾」只在**实现**层出现：`_edge_expandable` 把两轴取合取）。

⇒ **① 抬升 `confidence` 不是「按类型-强度映射纠正」**，而是**人工覆盖模型自报的数值** ⇒ 属**改证据**，
须以**人工裁决**留痕（`human_review_*` **不得由 AI 填值**，红线 7）。

### 5.3 ⚠️ 证据表的两个分支是**跨轴推断**

证据表给的两条路是「类型判定**正确** ⇒ 保持 `strong`」／「类型判定**偏高** ⇒ 改 `weak`」
—— 它们用**类型对不对**去决定 **`conf` 该不该升**。而 `conf` 的高低**不由类型决定**（5.2）
⇒ **「类型对」不构成「`conf` 应 > 0.6」的理由**。⇒ 这是本项目**同族**又一次：
**把一个间接的东西（类型判定）当成了直接可读的结论（数值该多大）**。
