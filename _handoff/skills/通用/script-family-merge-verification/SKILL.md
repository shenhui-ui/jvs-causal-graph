# 同源脚本族合并 + 等价性验证

## 一句话

**先证明「这族到底同不同构」，再决定按什么轴拆子命令；等价性只能靠 A/B 机械核验，不能靠肉眼。**

来源：JVS 项目 2026-09-20 的 `_migrate/` 命名族合并（11 → 4 个脚本）。三条坑都是那轮
**实测撞出来**的，不是推演。

---

## 第 0 步：先判定「真同构」还是「重写」（**不要假设**）

命名族 / 编号族 / `*2.py` 这种命名**极其容易骗人**。同一族的脚本可能：

| 形态 | 判据 | 处置 |
|---|---|---|
| **真同构** | 骨架逐行相同，只有常量 / 目标 / 载荷不同 | 参数化即可（如 `--case`），收益最大 |
| **多轮追问 / 重写** | 行数差大（实测 218 / 182 / 167），扫描口径、抽样上限、扩展名集各异 | **不能参数化**，只能按**能力**重排 |
| **同一段代码抄两遍** | 看似相同，**实际并不逐字相同** | 逐行 diff 找出差异，**差异要么参数化、要么显式统一并记录** |

**做法**：先逐份读全文，列出「差异轴」（目标、常量、口径、输出格式、抽样上限、扩展名集……），
再判断能否用一个参数覆盖全部差异轴。

> ⚠️ **实测反例**：`git_recon{,2,3}` / `exclusion_impact{,2}` / `verify_sse_equivalence{,2}` 三族
> 都不是参数化变体；4 族里**只有 `append_ws_memory{,2,3}` 真正同构**（同骨架，仅 target / sentinel / 载荷不同）。
> 若按「命名族 = 近同构」的假设直接开工，会写出一个谁都看不懂的超长参数表。

---

## 合并口径：按**能力**拆子命令，不按原脚本拆

- ❌ 按原脚本拆：`cmd_impact1()` / `cmd_impact2()` / `cmd_final()` ⇒ 只是「三个文件塞进一个」，
  **一行重复都没消掉**。
- ✅ 按能力拆：`inventory` / `dangling` / `zip-dir` / `sse-content` / `code-deps` / `png` ……
  ⇒ 真的把重复的骨架收敛成共享助手（`walk_*()` / `read_text()` / 共用正则 / 共用常量）。

子命令表写进模块 docstring，每行标出来源（`← impact1 §A`），接手者能一路追回去。

**允许的合并动作**（都是「消重复」而非「改语义」）：

- 共享遍历器（原脚本把「跳过 `.git` / `__pycache__`」那行抄了 8 遍 → 收敛为 1 处）
- 共享读取助手（体积门限 + `try/except` 合并为一个 `read_text(p, max_mb)`）
- 进程内缓存（原 7 个子命令各走一遍全库 → `collect_*()` 缓存为 1 次）
- 参数化**真正**重复的那一段（如 `dup --root`，原来同一段代码抄两遍）

**必须显式记录的动作**（不记录就等于偷偷改语义）：

- **有意省略的死代码**（定义后从未使用的名字、残缺表达式、恒为空的变量）—— 在模块头逐条列出
- **口径收敛**（如三份重叠清单合并为一份并集）—— 说明「对三者均为超集」并用脚本证明不丢行
- **统一历史遗漏**（如某一份漏了末尾明细块）—— 加参数让**两个原始节都能精确复现**
  （实测：`dup --top 0` 复现 §5、默认 `--top 8` 复现 §4）

## A/B 验证脚本的骨架

验证脚本放**工作区之外**（本环境会回滚工作区内的编辑），逐条打印判据结果，退出码 0 = 通过。

```python
SEP_RE = re.compile(r"^[=\-]{5,}$")
HDR_RE = re.compile(r"^\s*\d+\.\s")          # 节标题（编号可能与合并后不同，允许不同）
LINENO_RE = re.compile(r"^(.+?\.(?:py|cjs|sh|md|js)):(\d+)$")   # file:line 的行号要归一

ENV = dict(os.environ, PYTHONHASHSEED="0")   # ⚠️ 见坑 1

def norm(text):
    out, n_lineno = [], 0
    for ln in text.splitlines():
        s = ln.strip()
        if not s or SEP_RE.match(s) or s.startswith("口径:") or s.startswith("\u26a0\ufe0f"):
            continue                              # 合并新增的注释行不算「凭空多出」
        m = LINENO_RE.match(s)
        if m:
            n_lineno += 1
            s = m.group(1) + ":<N>"               # 行号易失，路径才是信号
        out.append(s)
    return out, n_lineno

def run(args):
    r = subprocess.run([PY] + args, cwd=JVS, capture_output=True, text=True,
                       encoding="utf-8", errors="replace", timeout=7200, env=ENV)
    return r.stdout + r.stderr, r.returncode
```

**主判据**：逐子命令，合并输出的规范化行集必须是其**来源原脚本**输出的子集
（`missing = [l for l in new if l not in orig]`，`missing` 必须为空）。

**辅判据**（视合并动作而定）：

- 真正重复的那一段：**逐行相等**（不是子集）
- 口径收敛：对每个原脚本均为**超集**（零丢行）
- `--top 0` 这类参数：与原节**逐行相等**

**★ 自证段（必加）**：原件输出必须含**预期标记**，否则中止。

```python
REQUIRED = {"recon1": ["扫描目录数:", "扫描文本文件数:"],
            "recon3": ["文件总数", "长度上限"]}
for key, marks in REQUIRED.items():
    blob = "\n".join(orig_lines[key])
    lack = [m for m in marks if m not in blob]
    if lack:
        fails.append("orig-" + key)
if fails:
    print("原件自证未过，后续比对无意义，中止"); return 1
```

> 少了这段，一旦原件路径写错（**归档后仍指原目录**），原脚本跑出来是「文件不存在」的错误文本、
> 原行集近乎空 ⇒ 要么 `IndexError`，要么**假通过**。这段是「**校验脚本必须自证**」的落地。
>
> ⚠️ **自证段本身也会写错 —— 实测撞过一次**：验证脚本的 `norm()` 只做了 `rstrip()` 没 `strip()`，
> 而原件的行是 `  文件总数 6299  体积 142.66 MB`（**有前导空格**）⇒ `l.startswith("文件总数")`
> 全部落空，自证报「出现 **0** 次」并中止。
> ⇒ **命中 0 先怀疑自己的写法，不是先怀疑被测对象**（同类纪律：`grep -cF` 返回 0 时先查自己的转义）。
> 自证段的价值正在于此：**它拦下的是「后面 6 组比对全都基于空集」的假通过**。
>
> ⚠️⚠️ **加强对「自己的写法」的怀疑 —— 同类事故本会话又在另一处复现两次**：
> ① `grep -cF "126 / 101 / 77"` 返回 **0**，实际文中写的是 `126/101/77`（**空格**）；
> ② `grep -cF "74 / 575"` 返回 **0**，实际文中写的是 `` 74 / **575** ``（**markdown 行内加粗**）。
> ⇒ 纪律升级：**凡把「人写的文档」当校验对象，比对前必须先「去格式」**
> （剥掉 `*` `_` `` ` `` 与多余空白），否则会在**正确的内容**上报假失败。
> 建议写法：
> ```python
> def deformat(t): return re.sub(r"[*`_]", "", t)          # 再配一次空白归一化
> assert needle_in(deformat(doc), needle)                   # 与原文比对时用去格式版本
> ```
> 判据：**一条判据若在语义正确时仍可能报错，那它是坏判据，不是严格判据。**
> （与 `repo-refactor-perf-survey` 的「测法必须与被保性质对齐」同源。）

**允许漂移的行要显式白名单化**，不能笼统放过：

```python
# 输出「工作区实时状态」（文件计数 / git status）的子命令，与运行时刻耦合，
# 不可能与缓存的原快照逐行相等 —— 非合并缺陷。判据改为：漂移行必须是「状态行」。
LIVE_STATE = {"secrets", "exclude-sizing", "repo01"}
# ⚠️ norm() 会 strip()，porcelain 状态码的前导空格被吃掉（` M path` -> `M path`），
#    所以不能写 `^ M`。
STATE_RE = re.compile(r"\d|^(?:\?\?|[MADRCU])\s")
bad = [l for l in missing if not STATE_RE.search(l)]   # bad 必须为空
```

## ⭐ 三条实测坑

### 坑 1：`PYTHONHASHSEED` 不固定 ⇒ A/B 不可比（**最容易误判成「合并有 bug」**）

只要输出里有「**按计数取 Top N**」这类**并列名次**，而候选来自**集合**迭代或 `dict` 插入顺序，
`str` 哈希的逐进程随机化就会让**同一份脚本自己重跑两次结果都不同**。

> **实测**：`dangling` 报 278 个被引用名，取 Top 25；其中大量**并列**（都是 36 处引用）。
> 同一时刻跑原文与合并版：**均 103 行 / 均扫 17955 个文件 / 均报 278 个被引用名**，
> 却有 **34 行不同**，且差异行引用数**全是 36** —— 纯并列次序。

**修法**：A/B 双方统一 `PYTHONHASHSEED=0`（写进 `subprocess` 的 `env`）。
**先跑「原文 vs 原文」两次**，若它自己就不稳，就别去查合并脚本。

### 坑 2：原件归档后，验证器必须改指归档路径

`git mv` 之后原路径不存在。验证器若仍指原目录：原脚本输出的是错误文本 ⇒ 原行集近乎空
⇒ `IndexError`，或更糟 —— **假通过**。

**修法**：验证器的 `ORIGINALS` 路径常量与「原件实际所在」**同时改**；再加坑 0 的自证段兜底。

### 坑 3：「同源」不等于「逐字相同」

「同一段代码抄了两遍」是**断言**，不是事实。实测 `git_recon3.py` §4（02 分区）与 §5（03 分区）
代码抄了两遍，**§5 却漏了末尾的 Top 明细块**。

**修法**：对声称重复的段落**逐行 diff**，差异要么参数化、要么显式统一并在 docstring 记录。
默认行为取统一口径，同时留参数让**每个原始节都能精确复现**。

## ⭐ 合并后加「加速器」（缓存 / 记忆化）

合并完成、A/B 全绿之后，常会想给某个子命令加**记忆化**（典型：`path + size + mtime_ns → sha256`）。
这件事有三个硬性手法，缺一个就会把 A/B 结论搞脏：

### 1. **opt-in，默认关闭** —— 让旧行为逐字可复现

`--cache PATH` 开启，**不加参数时行为与加缓存前逐字一致**。
⇒ 这样「旧行为」永远有一个**不需要任何白名单**的复现方式，A/B 也不会因为「这次跑用了缓存」而漂移。

### 2. **诊断信息走 `stderr`，`stdout` 只放报告**

命中率 / 缓存条目数这类统计打到 `stderr` ⇒ **`stdout` 在「有缓存」与「无缓存」下逐字相同**，
A/B 判据可以直接比**未归一的原始 stdout**，不需要「把新增的那两行加进白名单」。
> 这是本技能里最省事的一招：**把噪声挪出被测通道，比事后打补丁归一化更可靠。**

### 3. **判据：只有「报告 / 盘点」语义才可接缓存；「校验」语义是禁区**

| 语义 | 特征 | 能否缓存 |
|---|---|---|
| **报告 / 盘点** | 结果只用于**统计**（重复率、分布、规模） | ✅ 可以 |
| **校验** | 目的是**证明字节没变**（冻结指纹、交付包核验、逐文件哈希比对） | ❌ **绝对不行** |

缓存一旦介入校验，校验就退化成「**证明缓存没变**」—— 正是它要防的那件事。
> **实测禁区**（JVS）：门禁的冻结指纹复核、`verify_delivery.py`、`compare_models.py`。
> **反例警示**：一份方案文档原写「对反复跑的**校验器**收益最直接」—— **方向反了**，
> 真正的落点是**报告**语义的那个子命令。方案里的这类方向性断言，落地时必须回头改。

### 4. **已知过期面必须写进模块头，并列出「本模块不声称能自动发现」的部分**

典型：**size 与 mtime_ns 都没变、内容却变了**（`git restore` / 解压覆盖 / 保留 mtime 的回写工具）
⇒ 缓存会返回**错的**哈希。缓解只有显式 `--invalidate PATH`。

### 5. **自证判据 = 抽样重算比对**（`--verify --sample N`，固定种子可复跑）

从缓存里随机抽 N 条，**重新从磁盘算**，与缓存值比对 ⇒ **不符必须为 0**。
另加 `--bench ROOT` 连跑两遍看**第 2 遍命中率**（应 ≈ 100%，否则缓存等于没生效）。

### 6. A/B 判据要**冷、热各比一次**

- `--cache` 第 1 遍（**冷缓存**）：`stdout` 必须 == `--no-cache`
- `--cache` 第 2 遍（**全命中**）：`stdout` 必须 == `--no-cache`
- 第 2 遍命中率 ≥ 99%
- `--cache` 与 `--no-cache` **互斥**（同时给 ⇒ 非 0 退出码，不静默取其一）

> **实测收益的量级规律**：缓存对「**文件数瓶颈**」分区收益 **>** 「字节瓶颈」分区
> （JVS：小文件多的分区 **9.1×**，大文件少的分区 **6.6×**）。
> 原因：前者的开销在 `open/close`，缓存把整块消掉；后者在吞吐，缓存只省重复读、省不掉第一遍。

## 归档顺序：**先归档，再验证**

1. 合并脚本写完 → 语法 / `--list` / 冒烟测一个便宜子命令
2. **先 `git mv` 原件到归档目录**（保留原相对路径），并逐条核验 `blob sha` 未变（应为 `R100`）
3. 再跑 A/B（验证器已指归档路径）—— 这样验证的对象就是**冻结副本**，与将来接手者看到的一致
4. 归档目录名带日期（如 `superseded-migrate-20260920/`），**不删原件**

> ⚠️ 顺序反了（先验证再归档）会浪费一轮：验证器路径一改，缓存的原件输出就作废。

## 收尾自检清单

- [ ] 模块 docstring：子命令表（含来源标注）+ 「合并口径」逐条差异说明
- [ ] 每个子命令都跑过一遍，退出码 0；`--list` 条数与子命令表一致
- [ ] 原件 `git mv` 归档，`blob sha` 逐条一致（`R100`）
- [ ] A/B 脚本四类判据全绿：自证段 / 子集 / 逐行（真重复段）/ 超集（口径收敛）
- [ ] 允许漂移的行**白名单化**并打印条数，不隐藏
- [ ] 若合并引入新参数，**两个原始节都能用显式参数精确复现**（写进 docstring 与提交信息）
- [ ] 文档同步：方案文档 / 交接文档 / 状态登记表 / 索引层重跑（见 `_handoff/DEFINITION-OF-DONE.md` §2）
- [ ] 索引层集合差：**未解释消失 0 / 非归档新增 0**；新增数 == 本轮归档件数
- [ ] 提交信息里写清**三条坑的实证**（数字、文件、行数），不要只写「已合并」

**若本轮还加了加速器（缓存 / 记忆化）：**

- [ ] opt-in（默认关闭）⇒ 不加参数时旧行为**逐字可复现**
- [ ] 诊断信息走 `stderr` ⇒ `stdout` 在两种模式下逐字相同
- [ ] 已核对调用方语义：**报告**才接，**校验**列禁区并写进模块头
- [ ] 模块头写明**已知过期面**与「本模块不声称能自动发现」的部分
- [ ] 自证判据可执行且已跑：`--verify --sample N` ⇒ **不符 0 条**
- [ ] A/B 冷、热各比一次，且第 2 遍命中率 ≥ 99%

## 常见误判速查

| 现象 | 先怀疑 | 不是 |
|---|---|---|
| 同刻跑两版差几十行，差异行计数全相同 | **坑 1**（哈希种子） | 合并逻辑错 |
| 原行集几乎为空 / `IndexError` | **坑 2**（原件路径） | 脚本崩了 |
| 「同一段代码」逐行比对不相等 | **坑 3**（历史遗漏） | 抄写错误 |
| 自证段报「标记出现 0 次」 | **自证段自己的归一化写错**（`rstrip` vs `strip`） | 原件坏了 |
| 关键串 `grep -c` 返回 0，但人眼看文里明明有 | **自己的串没去格式**（空格 / markdown `**` `` ` ``） | 内容丢了 |
| `file:line` 行号整体位移 | 文档被编辑（正常） | 合并改了逻辑 |
| 计数 / `git status` 类行不同 | 实时状态（正常） | 合并改了逻辑 |
| 加缓存后 A/B 多出两行 | **统计没走 `stderr`** | 缓存改了结论 |
| 「加缓存后校验还是过了」 | **校验语义不该接缓存**（已退化成「证明缓存没变」） | 缓存没问题 |
