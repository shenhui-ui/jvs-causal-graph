# 未评指标的补评与锚点自证

## 一句话

**「未评」不等于「没人做」，很可能是「没人能算」** —— 先分诊，再重算；
重算的**第一件事不是算，是复现别人已经登记过的数字**。

## 0. 分诊（先做，别急着算）

看到「⏳ 未评 / 无数据 / —」，先问一句：

| 形态 | 特征 | 处置 |
|---|---|---|
| **A. 没人做** | 有计算者、有链路，只是没人跑 | 跑一遍即可 |
| **B. 没人能算** ⭐ | **链路里没有这个字段** | 先做**口径溯源**（见 §1） |

**B 的典型成因（本项目实测）**：**换生产通道时字段未迁移**。
把「规则判分器」换成「LLM 判分器」时，旧通道产 `qualified / evidence_score / format_ok`，
新通道只产它自己关心的那几个字段 ⇒ **该指标从此没有计算者**，
而**文本没错、代码没错、产物也没错** ⇒ 属于**静默过期**（本项目第 20 形态）。

**判据**：**凡「某指标未评」，先查「它在哪条链路上被算」，而不是查「谁忘了跑」。**
取证：全库搜该字段名，看它**只出现在哪些产物里**（如 `end_to_end_qualified_rate`
只存在于骨架管线的 `scores.json`，正式口径产物里一个都没有 ⇒ 判 B）。

## 1. 补评四步

1. **口径溯源** —— 找到**逐字**的口径定义（README / 规范 / 立项书），**照抄公式**，不要凭印象。
   例：`qualified = 可用 ∧ 三要素全对 ∧ evidence_score>=1.0 ∧ format_ok`；
   `率 = 合格 ÷ 可用`（另给「全量分母」保守口径）。
2. **拆轴重算** —— B 类问题的本质是**指标 = 两个轴**，而两个轴被换通道拆散了：
   **轴 1 = 新通道产出的**（如 LLM 判分的三要素）｜**轴 2 = 规则可算的**（如证据/格式）。
   把两轴**重新合起来**即可，**不需要重跑 LLM**。
3. **锚点自证** —— ⭐ **先复现「已登记的官方数字」**（如「可用 29/30」「三要素全对 21/30」）。
   对不上 ⇒ **立刻中止**（`rc=1`），不要继续算。
   ⚠️ 这一步同时回答「我读的是不是**官方那一对**产物」—— 同一目录常有多个支线 run，
   数字接近但口径不同（例：`final_merged` 是 22/30 的**合并变体**，项目已明确不合并）。
4. **口径敏感性** —— 至少给两种口径（如「官方原始」vs「合并补判」），并**指明哪个是官方值**。
   **结论对口径稳健**才算结论（两种口径同向 ⇒ 可信）。

## 2. 自证三件套（缺一不可）

| # | 手法 | 判据 |
|---|---|---|
| ① | **锚点** | 先复现已登记数字，对不上即中止 |
| ② | **负向** | **逐条篡改**输入（如抹掉一条 `[src:]`）⇒ 结果**必须变化**（Δ 可预测）⇒ 证明该轴**真接线**，不是恒真探针 |
| ③ | **独立第二实现** | 换一套解析路径重算（`json.load`+dict join ↔ 逐行原始文本+正则+集合运算），**逐项同值** |

⚠️ **没有 ② 就没有证据** —— 「算出来了」和「算对了」是两件事；
一个恒真的判据也会给出一个数。

## 3. 坑表（实测）

| 坑 | 症状 | 修法 |
|---|---|---|
| **出处张冠李戴** | 「数字 21/30」的出处写作某份**报告名**，而那份报告其实是**另一条管线**的口径（20.0%） | 出处**精确到「哪一次运行的哪个产物」**（`…/outputs/<run>/scores-sn.json`），不写报告名 |
| 同一份报告既对又错 | 报告自身没错（老实写了它的数），错的是**别人引用它** | 引用前 `grep` 该数字在**源产物**里的现值 |
| 恒真探针 | 检查「会通过」而不会「拒绝」 | 走 §2 ② |
| 分母漂移 | 「可用基础」与「全量分母」混写 | **两个都报**，并写清哪个是主口径 |
| 把补评说成重跑 | 声称「复现了当日 LLM 行为」 | 明写「**补评（back-fill）**，只读冻结产物，不声称复现当日行为」 |

## 4. 收尾（文档同步，别漏）

1. **全库搜旧表述**（分词搜，不用长串）—— 本项目实测同一句「⏳ 未评」出现在 **8 个文件**里。
2. **分清手写与生成** —— 生成物（`PENDING.md` / `_index/*`）**改产物无效**，必须改**生成器**
   （`status_map.py` / `make_progress_md.py` / `make_index_md.py`）再重跑**六步**。
3. **核验读 HEAD 不读工作区**：`git show HEAD:<f> | grep -cF "<串>"` 必须为预期值，
   旧表述必须为 **0**。
4. ⚠️ **`grep -F` 不解析转义** —— 用 `\|` 做多串或 `^` 做锚点都会**静默命中 0**；
   逐串单独 grep，或改用 `grep -E`。
5. 若改动落在**公开层内**（`README.md` / `_handoff/` / `_migrate/` …），
   **必须重跑「计划 → 构建 → 核验 → 推送」**整条链（推送属对外动作，须授权）。
