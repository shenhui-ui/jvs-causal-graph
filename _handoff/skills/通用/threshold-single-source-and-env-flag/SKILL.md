# 阈值单一真值源 + 门控三态

## 一句话

两类**静默失效**常同时出现：① 同一个阈值在**文档与代码各写一份**，谁也没错但没人能回答「到底是几」；
② 布尔门控写成**裸真值**，`=0` 反而**开启**功能 ⇒ 复跑口径不可复现。
两者的共同点是**不报错、结果看起来正常**，所以只能靠「改一处 ⇒ 结论必须翻转」的自证抓出来。

## 0. 适用 / 不适用

**适用**：某判定逻辑的**阈值/口径**同时出现在规范文档与实现里；或某功能由环境变量开关控制，且该开关值会写进复跑记录。
**不适用**：阈值只有一个出处且没有文档承诺；开关只在本机临时用、不进复跑记录。

---

## 一、阈值收敛到单一真值源

### 步骤（缺一不可）

1. **建配置文件**（如 `xxx.yaml` / `xxx.json`），把「类别定义 + 阈值 + 优先级」全部搬进去。
   同时写 `status` 字段如实登记状态：`draft_pending_ruling` 还是 `locked` —— **不一致未裁定前不许写 locked**。
2. **把「文档 vs 实现不一致」登记成待裁定项，写进配置文件的 `pending_rulings`**（含 `id` / `question` / `why_not_ai` / `current_value` / `alternative` / `evidence`）。
   ⛔ **不要自己选一个**：规范原文与实现的偏离属**口径解释**，不是实现者可以私了的语义问题。
3. **代码只从该文件读**，不得再留第二处硬编码；读取函数对残缺配置**抛错**（缺类、缺优先级、非法字段一律拒绝，不许回落默认值）。
4. **参数化而非写死**：阈值/读数口径（如 `max` vs `min`）、优先级顺序都从配置取。

### 验收（**必须能拒绝**）

- **改配置 ⇒ 同一输入换结论**：把阈值抬到样本之上、把 `max` 换成 `min`、把优先级重排 —— 每一个都要能**改变判定**。改不动 = 其实是硬编码。
- **配置驱动测试必须自证**：写一条用例断言「阈值抬到 X 后同一输入必须换类」，而不是只断言「默认配置下判成 Y」。
- **读数口径也要单测**：同一批数据在两种读数下**结论相反**，就是「口径分歧」的机械举证 —— 比写一段「存在口径歧义」的说明有力得多。

### 优先级不要掩盖重叠

命中多个类别时：**「命中了哪些类」用规范顺序输出**（与优先级无关），**胜出者才按优先级取**。
否则重排优先级会连带改动命中清单，把真实重叠藏起来。

### 形态 3：同一「枚举 / 顺序」被多个消费方各存一份（2026-09-30 实测新增）

阈值只是「**一个数**」；同一家族还有「**一组键 + 顺序 + 显示映射**」。
它的副本往往**不是**文档 vs 代码，而是**两个兄弟消费方各写一份**，
外加**调用点再硬编码一次顺序**：

```python
# a_make.py
BADGE = {"已开发": "✅ 已开发", "开发中": "🔧 开发中"}     # 副本 1
...
for k in ["已开发", "开发中", "待开发", "待规划"]:          # ← 顺序又硬编码一次
    if counts[k]:
        out.append(BADGE[k])

# b_make.py
BADGE = {"已开发": "✅ 已开发", "开发中": "🔧 开发中"}     # 副本 2（与副本 1 无人比对）
```

**为什么比阈值更隐蔽**：两份副本**当前一致**，所以任何一次「只改一处」都**不报错** ——
产物只是**两份文档对同一项给出不同标记**。硬编码列表更狠：`if counts[k]` 只认
列表内的键 ⇒ **新增枚举值静默消失**（无异常、无提示、无日志）。

**修法（一条链，缺一不可）**

1. **收敛到元组**：`STATUS_BADGE = ((key, badge, legend), ...)` ⇒ **顺序 = 元组顺序**，
   由它派生 `ORDER = tuple(k for k, _, _ in ...)` / `MAP = {k: b ...}` / `LEGEND = {k: d ...}`。
   ⚠️ **顺序与优先级是两个轴**：木桶 / 优先级另立一个元组（`RANK`），**只校验二者同集合、
   不合并顺序** —— 否则重排优先级会连带改动显示序（同 §一「优先级不要掩盖重叠」）。
2. **消费方只 `import`，不留副本**；调用点改**遍历 `ORDER`**，不写字面量列表。
3. **渲染前拒绝**：`require_known(seq, where)` —— 未登记值 **`raise`**，**不静默回落**。
4. **留一个全局自检**：`check_status_keys()` 断言「所有取值集合 ⊆ ORDER」且「`RANK` 与 `ORDER` 同集合」。

**验收（三条，缺一不可）**

- **改一处 ⇒ 结论翻转**：给元组加第 5 项，新写法**带上它**、旧硬编码列表**仍丢它** ——
  两者结论必须**相反**（否则这组用例分辨不出回归）。
- **反恒真**：直接算出「旧写法对第 5 项渲染 **0 次**」，而不是只断言新写法渲染了 1 次。
- **定义点计数 = 1**：全库扫**定义形态**（如 `^BADGE\s*=`，别只搜字符串），命中必须恰好 1 处；
  **把这个数写进提交说明**，否则下次有人再加副本无人发现。

## 二、门控三态（`0/1` 环境变量）

### 缺陷形态

```python
if os.environ.get("FEATURE_X"):          # ❌  "0" 为真 ⇒ 置 0 反而开启
rev_ok = bool(os.environ.get("FEATURE_Y"))  # ❌ 同上
```

### 正确实现

```python
def env_flag(name, default=False):
    raw = os.environ.get(name)
    if raw is None or raw.strip() == "":      # 未设置 / 空串 ⇒ default
        return default
    return raw.strip().lower() not in ("0", "false", "no", "off")
```

### 三态自证（**判据是「行为各异」，不是「都返回了」**）

| 取值 | 期望 |
|---|---|
| 未设置 | `default` |
| `""` / 纯空白 | `default` |
| `0` / `false` / `no` / `off`（含大小写、首尾空白） | `False` |
| 其余非空（`1` / `true` / `yes` / `x`） | `True` |

再加两条**反恒真**用例：

- **重放旧实现**（`bool(os.environ.get(...))`），断言新旧在 `"0"` 上**结论相反** —— 否则这组用例分辨不出回归。
- **断言修复不改变历史上真正用过的取值**（通常是「未设置」与「`=1`」）⇒ 证明历史复跑口径未被动过。

### 防复发：形态检测器

用正则扫描源码，禁止裸真值门控再次出现：

```python
BARE_GATE = re.compile(r'(?:if|and|or|not)\s+os\.environ\.get\("[A-Z_]+"\)\s*(?=[:\n]|and\b|or\b)')
BOOL_WRAP = re.compile(r'bool\(os\.environ\.get\("[A-Z_]+"\)\)')
```

⚠️ **检测器自身必须自证**：把**修复前**的代码喂给它，必须命中；对本版必须命中 0。否则它是装饰品。
⚠️ 正则要排除**合法**的取值型读取（`os.environ.get("X") or fallback`、`get("X","1") != "0"`）—— 实测粗正则会误报这类。

## 三、改遍历/判定逻辑后的 A/B（同族必做）

若改动触及**遍历或判定顺序**，**不得只比「集合相等」**：
关掉一条边可能让节点集合几乎不变，而**边序列大量变化**（「谁先认领节点」被扰动，甚至出现**新增**）。
⇒ 必须**调真实入口跑前后、比有序输出的逐字段快照**；差异为零**或逐项解释**。
⇒ 同一逻辑若有**多套实现**（各自复制了一份判据函数），**必须全测**。

## 四、实测坑（照抄会踩）

1. **比对器也要可读**：首版把整份列表打印出来（十万字节输出）等于没比对 ⇒ 改成「按字段统计 + 只列 id 增减」。
2. **测试夹具的转义会伪装成代码缺陷**：shell 双引号里的 `\t` 传到 `python -c` 后不一定还是 Tab ⇒ 曾误报「未拒绝 Tab」。**判「代码有 bug」前先确认夹具没被改写**（用 `chr(9)` 复现）。
3. **无第三方库时不要引入重依赖**：本机常无 PyYAML。写一个**只认自己子集、读不懂即抛错**的极简读取器，比放宽解析器安全（静默忽略语法 = 静默失效）。
4. **配置文件的路径统计要注意字段类型**：SQL/JSON 里数值字段被存成字符串时，比较会**静默返回 0**。先打 `typeof(字段)` 再写阈值统计。
5. **A/B 的「允许变化区域」判据用行号区间，别用行内容正则**：`🗓️` 是 U+1F5D3 + U+FE0F
   **两个码点**，写进字符类会被拆成两个候选 ⇒ 把合法变化误判成「越界」。
   **夹具缺陷会伪装成代码缺陷**（同 §四 第 2 条）：判「重构非等价」前先确认是判据错还是代码错。
6. **`subprocess(text=True)` 会做 universal-newline 转换**：拿它与 `newline=""` 读出的文本比，
   CRLF 文件**必不相等** ⇒ 会制造出**满屏假差异**。比字节一律走 **bytes 模式再手工 decode**。
   同理，**「与 HEAD 逐字节一致」类判据**要先把**易变行**（如生成器自述的「生成时 HEAD」快照）
   声明出来，否则每次复跑都报假失败。
