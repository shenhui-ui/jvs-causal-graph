# 巨函数拆分与行为等价验收

## 一句话

把巨型函数按**可命名的阶段**抽成模块级私有函数，用**三层递增强度的 A/B 证据**证明行为逐字节不变；
**先有回归件，再动刀**。

## 何时用

- 要拆一个数百行、圈复杂度上百的函数（`validate_*` / `main` / `verify` 这类）
- 要回答「拆完怎么证明行为没变」
- 手上有回归件，但不确定够不够格当安全网
- 拆完后文件变长了，不确定算不算失败
- A/B 对比跑到一半被前台超时杀掉

## 流程

### 第 0 步：先判「能不能拆」

三个前置，缺一个就别拆：

| 前置 | 判据 |
|---|---|
| 目标**仍在活跃使用** | 一次性脚本拆了是**净负收益**（只登记不重构） |
| 目标**已有活回归件** | 没有 ⇒ 先补特征化回归件（见技能 `characterization-regression-harness`），并**接入门禁** |
| 目标**不在冻结面** | 在冻结指纹清单里 ⇒ **不能拆**（拆了等于改冻结产物） |

> 「回归件已绿」**不等于**「拆已授权」。拆分须**逐项授权**，一次一个。

### 第 1 步：钉基线，且基线自己要先跑通

记录：**行数 / 圈复杂度（必须附口径）/ sha256 / 字节数 / 原始 stdout + 退出码**。

⚠️ **基线脚本自己跑不过，后面所有 A/B 都是假的。**
基线在拆前**复跑一次**，确认它给出的是「通过」而不是「意外失败」——
基线首跑失败时，**先查是不是环境问题**（路径、软链接/junction、缺依赖），
不要直接把它记成「已知失败」。

### 第 2 步：切分点按「可命名的阶段」定，不按行数

每段给一个能说清职责的名字（`check_*` / `load_*` / `build_*` / `validate_*`）。
抽完后**原函数只剩调度** —— 行数与圈复杂度都应**显著**下降，否则说明切错了。

### 第 3 步：写可复现的变换脚本，不要手改

- 从**原始副本**读、往**仓库**写（原始副本留在工作区外）。
- 每次拼接**断言锚点唯一**；写完先 `ast.parse` 再落盘。
- ⚠️ **拼接顺序是承重的**：先把「调用方」改完，再插「被调函数」。
  反过来会撞上「锚点不唯一」—— 因为被调函数的函数体里**逐字包含**调用方那几行。

### 第 4 步：保住语义的三个细节（最容易漏）

1. **原地 append 的对象要传「对象本身」** —— 若被抽函数要把结果 append 进调用方传入的 list，
   必须传那个 list，**不能在函数内 rebind**，否则调用方拿到的是空的。
2. **真值语义要先归一化** —— 原逻辑若用 `if x:` 判真值，而 `x` 可能是 `None` 或非 list，
   传入前先 `x = x if isinstance(x, list) else []`；否则抽函数后 `if x:` 的含义变了。
3. **不得改变任何 append 的顺序**。

### 第 5 步：三层 A/B（证据强度递增，逐层都要做）

| 层 | 做法 | 能证明什么 |
|---|---|---|
| ① CLI 文本 | 同一输入下比 **stdout + 退出码 + 产物 sha256**，**逐字节** | 端到端可见行为不变 |
| ② 单元返回值 | **in-process** 同时载入原/新两个模块，对**大量真实样本**比返回值 | 覆盖真实数据分布 |
| ③ 定向变异 | 构造**多个互不相同**的错误分支输入，比返回值 | 覆盖错误路径 |

⚠️ **② 必须 in-process。** 把每个样本 spawn 成一次 CLI 进程会**远超前台超时**并被 SIGTERM，
而且「跑不完」会被误读成「有问题」。
⚠️ **③ 的每个变异必须触发互不相同的错误。** 变异之间若报同一条错，等于只测了一条分支。
⚠️ **③ 的变异必须「在夹具上可观测」** —— 否则你测的是**变异设计**，不是等价性。实测踩过两类**白跑**：
① **语义等价变异**（改条件不改消息 / 改阈值但夹具取值不跨阈值 / 改一个只读分支）⇒ 新旧行为本来就一样；
② **变异被其它逻辑吸收**（如把 `start = marker + 1` 改成 `+ 2`，被紧随其后的 `while` 裁剪循环吃掉）。
判据 = **每个变异都要断言「预期错误确实出现」**；出现不了就改**变异**，别急着报「分支未覆盖」。
⚠️ 目标输出本身不稳定时，① 降级为「**归一化 stdout**（去计数行 / 耗时行）+ 产物 `sha256`」，
并在回归件里**显式声明**。

⭐ **③ 要给机械判据，不要只给「互不相同」这句话。**
「互不相同」靠人眼判不出来。做法：**捕获异常的 `traceback` 最后一帧，映射成
「函数名 @ 行号」= 触发点**，要求全部变异的触发点**去重后条数 == 变异条数**。
（基线/新件的触发点**本来就必须不同** —— 拆分把断言搬进了新函数；
故触发点只用于**变异之间**去重，**不参与**「基线 == 新件」的比较。
后者只比「异常类型 + 消息」。）

⭐ **「变异被别的逻辑吸收」有三种形态，判据是抓它们的唯一手段**（实测连踩三次才过）：

| 形态 | 表现 | 修法 |
|---|---|---|
| **清单有多列** | 输入清单除「文件→bytes/sha256」外**还有第二列派生值**（如另一张「来源哈希」表） | 变异的刷新函数必须**同时**更新**所有**与被改文件相关的列，否则在更早的断言处被截获 |
| **被测输入内嵌了副本** | 被测对象是「合并包 / 归档」，内部**逐文件复制**了源文件（如合并 ZIP） | 改源文件后必须**同步替换内嵌副本**；且若刷新函数改写了清单文件本身，而**清单也是内嵌成员** ⇒ 它也要同步 |
| **夹具写坏** | `open(p,"w").write(open(p).read() …)` —— `open(w)` **先截断**，读到空串 | 先读后写，分两句 |

⇒ **只比对「有没有报错」会全绿假过**：上面前两种形态下，新件与基线**都会报错、且报的是同一条**，
看上去「一致」，实际你只测了**那条更早的**分支。

> ⭐ **强烈建议再补一层 ④ 结构等价（成本极低、信息量最大）**：逐函数比对**源码片段**
> （`ast` 取 `lineno..end_lineno` 拼回原文），列出「**一字未改**」「已变」「新增」三张清单。
> 判据：**越界改动 = 0**（只有拆分目标允许出现在「已变」里）。
> 价值：凡未改动的函数，其**全部边界行为**（长度阈值、置信阈值、行裁剪、比较符）**天然等价** ——
> 于是**不必**为每个阈值单独造边界夹具，也不必依赖回归件是否恰好覆盖了某个边界。

### 第 6 步：判据逐条给证据，不给结论

| 判据 | 要给出什么 |
|---|---|
| 回归件 | **拆前已绿、拆后仍绿**（附测试条数） |
| 结构确实下降 | **目标函数**的行数与圈复杂度**严格小于**基线 |
| 冻结面 | 冻结指纹仍**逐条一致** |
| 过期登记 | 变更说明列出**新增的过期条目**（哪个快照的哪一条、旧值 → 新值） |

⚠️ **文件总行数变大是正常的** —— 抽函数**必然**加行。
⚠️ **不得**用「全库行数下降」当判据。

### 第 7 步：落库

分支与合并**只用安全写法** —— 见技能 `git-sigterm-safe-recovery`（本环境禁 `git switch` / `git checkout`）。
提交后**回读 `HEAD`** 核验，**不要读工作区**（工作区可能被回滚）。

## 抗理性化

| 借口 | 事实 |
|---|---|
| 「纯结构重排，肉眼看着一样，A/B 可以省」 | 肉眼不看 append 顺序、不看真值语义、不看错误分支 |
| 「回归件已经绿了，够了」 | **恒绿的回归件 = 没有回归件** ⇒ 必须做**负向自检**（人为改坏一处，确认它会红） |
| 「② 的样本上百个了，③ 不用做」 | 真实样本多半只走 happy path；**错误分支要靠变异专门打** |
| 「文件从 N 行变 N+M 行，说明拆失败了」 | 判据是**目标函数**的行数与圈复杂度，不是文件总行数 |
| 「A/B 跑不完，这一层先跳过」 | 跑不完是**设计**错了（spawn 太多进程）⇒ 改成 in-process，**不是删掉这一层** |
| 「基线首跑就失败了，记为已知失败吧」 | 基线**必须先跑通**；首跑失败先查环境（路径 / junction / 依赖） |
| 「先拆完再补回归件也一样」 | 拆完就没有「拆前」可比了，回归件只能证明**拆后**的样子 |
| 「负向自检我跑过了」 | 自检的目的是**制造红**；变异必须**在夹具上可观测**。实测一版 6 个变异只抓住 1 个，复查后 4 个是**语义等价变异** ⇒ 那一轮测的是变异设计 |
| 「每个阈值都造个边界夹具才稳妥」 | 先做 **④ 结构等价**：含该阈值的函数若一字未改，其边界行为**天然等价** |
| 「19 个变异基线/新件都报同一条错 ⇒ 等价成立」 | 报同一条错可能说明**它们全被更早的断言截获** ⇒ 只测了一条分支。必须报**触发点去重数 == 变异数** |
| 「回归件拆前就不是全绿，那 R4-a 只能算了」 | 先判**是不是环境**（换执行路径复测：bash→python vs PowerShell 可分辨 OS 层与沙箱层）。是环境 ⇒ 记「**拆前拆后逐字同一**」（同 `Ran N tests` / 同结论 / 同一失败用例名）并**单独登记**，不算通过也不算失败 |
| 「拆前拆后不一致，说明改坏了」 | 先查判据本身：`Ran N tests in 3.1s` 的**耗时**、`-v` 输出里 `test_mod.X` vs `__main__.X` 的模块名，都会让「逐字比较」假报不一致 |

## 红旗

- 回归件从写出来到现在**从没红过**
- 拆完后**目标函数的圈复杂度没降**
- 变异用例里出现**重复的**错误分支
- 变异是「**语义等价变异**」（改了但夹具看不出来），或**变异被别的逻辑吸收**
- ③ 层**只报了「一致/不一致」而没有触发点去重数**（无法证明覆盖了几条分支）
- ③ 的刷新函数只更新清单的一列，而该清单**还有派生列**；或没识别出**被测输入内嵌了文件副本**
- 拆前不是全绿却**没查是不是环境**、也**没记「拆前拆后逐字同一」**，就把它当已知失败放过
- 有未改动的函数却**没做**逐函数源码片段比对（等于放弃了「省夹具」的正解）
- 用了「全库行数」当判据
- 拼接脚本**没有锚点唯一性断言**
- 复核时读的是**工作区**而不是 `HEAD`
- 基线从未在**拆前**复跑过

## 校验（收尾）

- 回归件在**拆前**能跑（有复跑记录）、**拆后**仍能跑
- 三层 A/B 各有**可复跑的脚本**留在**工作区外**
- 已做 **④ 结构等价**：给出「一字未改」函数清单，且**越界改动 = 0**
- 落库后：`HEAD` 里目标文件的 sha256 == 声称值；目标函数的行数 / 圈复杂度**现测** == 声称值
- 目标函数的**圈复杂度口径**已随引用一并给出（换节点集合会得到差 1 或多个的值）
- 通用收尾序列见 `_handoff/DEFINITION-OF-DONE.md`（相对 JVS 仓库根）
