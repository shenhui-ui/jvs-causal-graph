# 特征化回归件（拆分前的「行为等价」底座）

## 一句话

**拆分前先写、先跑绿、并入库** —— 没有回归件的「拆巨函数」无法验收（拆完只能靠人读）；
而**恒绿的回归件等于没有回归件**，所以写完必须再做一次**负向自检**。

## 0. 适用 / 不适用

**适用**：某函数即将被**纯结构重排**（抽子函数 / 拆模块），且它**没有单元测试**。
判据：只要「拆完要靠人读才能相信没改坏」，就必须先补本件。

**不适用**：功能还在变（此时要写的是**规格测试**，不是特征化测试）；纯新增代码。

> ⚠️ 特征化回归件钉的是「**现在的行为**」，不是「**正确的行为**」——
> 它**故意**把当前的怪癖（写死的常量、只做形状校验不做语义校验、不可能的日期也放行）也钉住。
> 将来这些怪癖被修，回归件**应当**随之改；那不是 bug。
> ⇒ 因此在件里**显式注明**「这是特征化而非正确性断言」，否则后人会把它当规格。

## 一、三件套范式

### ① 夹具：自建 + 可复位（最关键）

- 用 `tempfile` **自建**最小夹具；**不要**拿生产数据当夹具（生产数据会变 ⇒ 假红）。
- 建完**立刻**存基线快照 `self.x0 = deepcopy(self.x)`，并写 `reset()` 复原。
- ⚠️ **每个 `subTest` 迭代的第一步必须是 `reset()`**（见 §二 坑 1）。

### ② 负向守卫：一条断言钉一条错误

- 正路径只断言「**除已知常量错误外零错误**」—— 把常量错误做成显式列表，
  这样常量一变，失败点直接指向那一行。
- 负路径逐条**钉错误文本**：封装 `self.invalid("...")`，内部断言
  `status != ok` **且** `needle in "\n".join(errors)`（见 §二 坑 2）。
- 检查串必须**从被测文件里抄**，不要凭印象写（凭印象写检查串是本项目高频假阴性来源）。
- 顺手为**被拆函数本身**加独立单元测试（如 `check_manifest` / `check_index_inventory`），
  这样拆分后即便主入口行为一致，也能定位到是哪一段变了。

### ③ 端到端基线：用真实产物，且 **fail-closed**

- 优先钉**真实交付包**的**完整返回字典**（键 + 值全量），而不是只钉几个字段。
- ⚠️ **真实包缺失时 `self.fail(...)`，绝不 `skip`** —— `skip` 会让「假绿」通过（见 §二 坑 3）。
- fail 信息里写清**期望路径**与「为什么不能 skip」。
- 加一条**只读证明**：测试前后对目录做 `(relpath, size, mtime_ns)` 指纹，断言一致。
- 基线值标注**测量日期**，并说明它是「特征化」而非「正确性」判据。

## 二、三条实测坑（都会造成**假绿或假红**）

| # | 现象 | 根因 | 修法 |
|---|---|---|---|
| 1 | 大量失败，且报错内容是**上一轮**的 | 变异辅助函数内部会 `save()` 落盘；下一轮从**已落盘的变异态** `deepcopy` ⇒ 变异**跨迭代累积** | 固定基线 `self.x0` + `reset()`，**每轮迭代先调** |
| 2 | 负向断言**永不命中**，报错文本还误导 | `assertIn(needle, list)` 是**精确成员**判断，不是子串匹配 | 先 `"\n".join(errors)` 再 `assertIn` |
| 3 | 回归件「全过」，但被测代码其实是坏的 | 基线缺失时用了 `skip` | 一律 `fail`（fail-closed） |

> ⭐ **坑 1 的教训**：第一版大量失败时，先怀疑**夹具**，不要先怀疑被测对象 ——
> 实测中 27 处失败**全部**源于夹具缺陷，被测对象一行没错。

## 三、负向自检（证明「不是恒真探针」）

写完必须再跑这个：

1. 在**生产路径**上写一个**单点变异**（改一个常量 / 改一个分支）。
2. 跑回归件 ⇒ 必须 **FAIL**，且**失败用例名**须是你预期的那个（**命中预期名才算过**）。
3. **同一次运行内**还原，并核验 `sha256` **逐字节一致**。
4. 复跑 ⇒ 必须 **PASS**。

判据：**「一个从不失败的检查等于没有检查」**。

⚠️ 还原必须**在同一次脚本运行内**完成 —— 本环境会**按行回滚**仓内编辑，
跨轮还原可能只还原一半（同文件一处还原、另两处保留）。
⚠️ 自检脚本本身放**工作区之外**，避免被回滚机制波及。

### ⚠️ 还原手法本身会踩坑（实测）

**不要**用 `git restore -- <path>` / `git checkout-index` 来还原探针改动：

- `git restore` **默认从索引（index）恢复**，不是从 HEAD。探针行若已 `git add` 进索引，
  「还原」等于把污染**原样写回工作区**（实测：probe 行残留、`git reset` 还顺手清空了暂存区）。
- 若非要走 git，须显式 `git restore --source=HEAD -- <path>`；但**本环境禁用
  `git checkout`/`git switch`**（必发 SIGTERM 并批量回收工作区文件），能不用就不用。

**正确做法：完全不依赖 git —— 跑前读进内存，跑完写回**

```python
orig = io.open(path, encoding="utf-8", newline="").read()   # ① 跑前存原文
try:
    io.open(path, "a", encoding="utf-8", newline="").write("\n# probe\n")
    ...  # ② 跑探针（含 git add / 跑门禁）
finally:
    io.open(path, "w", encoding="utf-8", newline="").write(orig)  # ③ 写回原文
assert io.open(path, encoding="utf-8", newline="").read() == orig   # ④ 逐字节核验
```

⚠️ 写回时用 `newline=""`（不做换行转换），并**整体写回原文**，不要靠「删掉注入的那一行」
来还原 —— `split("\n")` 对以换行结尾的文件会多出一个尾部空串，删行后会**多留一个尾部空行**，
逐字节比对必然不等（实测踩到，是本次唯一残留污染的原因）。

## 四、与「拆分验收」判据的接口

本件是拆分验收的**前置件**。项目若已有拆分判据，通常是这两条：

- **R4-a 回归件先存在、先绿** —— `python -B test_<目标>.py` 末行 `OK`，**拆分前**必须已绿。
- **R4-b 行为等价** —— 同一输入下，拆分前后**原始 stdout 文本 + 退出码**逐字一致。
  ⚠️ **不得用「本轮新增 FAIL 数」作判据** —— 同一输入并不保证输出稳定（既有校验器用过
  锁 / 节流，重复跑会得到不同条数）。
  若目标输出本身不稳定，R4-b 降级为「**归一化 stdout**（去计数行 / 耗时行）
  + 产物 `sha256` 逐字节一致」，并**在回归件里显式声明**哪些行不参与比对。

⇒ 所以回归件要**留好接口**：能被外部以「只跑、只看末行 `OK`」的方式调用（`unittest.main()`）。

## 五、收尾

通用收尾序列见 `_handoff/DEFINITION-OF-DONE.md`（相对 JVS 仓库根）。本技能专属项：

- 回归件**必须入库** —— 判据 `git ls-tree -r --name-only HEAD -- <path>` 命中；
  **未入库的回归件对下次会话不存在**。
- 若回归件落在**被索引的路径**下，须重跑索引层六步
  （见技能 `jvs-index-layer-maintenance`）。
- 报告里要写清：**测试数、负向自检结果、真实包路径**。
- ⚠️ 若门禁里有「跑回归件」的步骤，注意它可能是**硬编码文件名**的 ——
  新件**不会自动接入**；接入属**门禁变更**，需另行授权，**不要顺手改门禁**。
