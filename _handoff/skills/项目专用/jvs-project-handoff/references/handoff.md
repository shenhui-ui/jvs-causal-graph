## 1. 保存

### 1.1 确定记录位置

1. 按**用户指定位置**保存；未指定时用**项目现有状态载体** ——
   本项目固定为 `_handoff/HANDOFF.md` **§12 交接记录**（登记表 + 状态机 + 评估登记），
   必要时配套刷新 `_index/` 索引层（流程见技能 `jvs-index-layer-maintenance`）。
2. **保留结构、增量更新** —— 只改需要改的字段，**不重排他人已写的部分**。
3. **写入前重读目标部分**；若已被其他任务修改，**先合并差异**，
   **不能用旧副本覆盖**，**也不得改动其他任务的部分**。
4. 无项目目录时（如纯咨询类任务），**在回复中交付**。

### 1.2 记录恢复所需信息

按下表取**实际存在**的内容；**合并重复信息**，**不复制整段聊天、全局规则或完整日志**。
**未知写「未确认」，未验证写「未验证」。**

| 内容 | 记录方式 | 本项目落点 |
|---|---|---|
| **任务与版本** | 目标、范围、完成标准、工作目录、更新时间。代码任务记**分支／提交位置及未提交改动**；其他任务记影响下一步的文档或素材版本 | `HANDOFF.md` §12 备注列 + `_handoff/PENDING.md` |
| **权威资料** | 文件路径及要查的内容；指定资料管理哪一部分。**存在冲突时标明冲突，不能自行宣布某份资料更权威** | `HANDOFF.md` §8 文件地图速查 |
| **决定与限制** | 区分**用户已确认 / Agent 建议或自行选择 / 未决**。关键决定附简短理由；**已否决路线附原因**，重议条件仅在已知时记录。保留**授权范围**与**待确认动作**；仍影响后续的旧决定，**标明被哪项新决定替代** | `HANDOFF.md` §10 已否决路线表 + `docs/host_memory_dump/M1-10-待裁定项决策记录-*.md` |
| **进展与运行状态** | 区分**已完成 / 进行中 / 未做 / 未验证**，附成果与验证证据位置。任务仍运行时记录可用的任务编号、查询方式、输出／日志位置；**不把半成品记为完成** | `HANDOFF.md` §9 四态表 + `_index/功能分类总表.md` |
| **接续动作** | 下一步、前置条件、阻塞项、验收方法；**记录已确认无效的路线及原因**，相关条件未变时**不重新采用**。已有提醒时记录原因、回应和适用范围 | `HANDOFF.md` §9「未做」+ `_handoff/PENDING.md` |

**交接区字段**（本项目 = `HANDOFF.md` §12 登记表）：

| 上游字段 | 本项目现名 | 说明 |
|---|---|---|
| 本次唯一编号 | **交接编号** | 规则 `JVS-HO-YYYYMMDD-NN` |
| 源任务编号 | **源** | 如「待裁定项清理会话」 |
| 用户确认的目录／动作范围 | **备注** | **不把建议伪装成授权** |
| 接手任务编号 | **接手方** | **未返回时留空** |
| 交接状态 | **状态** | 5 态见下 |

**状态机 5 态**（已落 `HANDOFF.md` §12）：

```
材料已核对 → 等待接手核验 → 准备接续 → 已接手
                                    ↘ 受阻
```

⚠️ **不能把「创建成功」写成「已接手」**。
⚠️ **同一次失败恢复沿用原编号，不另建一套任务事实文档。**

### 1.3 回读核对

- 确认文件**已写入**、**路径正确**、**必要引用可访问**
- 核对**关键决定**与**下一步**是否与用户要求一致
- **缺失文件、未保存成果、不可访问引用**要**明确报告**
- 可跨机器使用的引用**注明项目根目录**；**仅本机可用的路径标明限制**
  （⚠️ 本项目有 **24 个 junction** 与大量硬编码绝对路径 ⇒ 此项**必做**）
- ⚠️ **凭据不写入交接**

### 1.4 准备入口

- **开场白**调用技能 **`jvs-project-handoff`**，给出：
  **项目绝对路径 + 交接来源与编号 + 当前目标 + 已确认限制 + 可执行的第一步 + 验收方法**
- **引用用户已经确认的接续范围**，**不把建议伪装成授权**
- **仅保存**时：交付**路径** + **可复制开场白**
- **完整交接**时：继续 §2，**不要求用户搬运材料**

### 1.5 保存的副作用边界

**不推送、不初始化仓库、不安装、不删除、不改配置** ——
这些动作只按**已有任务授权**与**当前规则**另行处理。

⚠️ **与上游的关键差异**：上游写「保存交接不附带提交」，
但**本环境会回滚工作区内未提交的改动**（粒度甚至不是整文件，见 `GIT-POLICY.md` §11 铁律 3）。
⇒ 本项目「保存」= **写文件 + `git add`（含新建目录）+ `git commit` + `git show` 复核**，
压在**单次运行内**。
**提交在本环境是「持久化手段」，不是「额外的副作用动作」。**

## 2. 自动接续（⚠️ 本宿主内**不可执行** —— 仅保留判据；2026-09-19 复评）

上游 6 步依赖的 Codex 工具，**WorkBuddy 宿主内建能力里一个都没有**：

`list_projects` / `create_thread` / `wait_threads` / `read_thread` /
`send_message_to_thread` / `navigate_to_codex_page`

⚠️ **但 2026-09-19 勘察 + 实测发现「部分有解」，本节口径须修正**：
本机 DSH `--profile acp` 提供 `session/new`（≈`create_thread`）/ `session/prompt`（≈`send_message_to_thread`）/
`session/list`（≈`list_projects`）/ `session/resume`，**零安装**，**已端到端实测打通**，
且**成品桥已交付**（`tools/host/acp_bridge.py` + `README-acp-bridge.md`）。
**然而**：① 寻址的是 **DSH 会话，不是 WorkBuddy 会话**；② **不能强制新会话「先只读核验」**
⇒ 上游第 3 步只能**软约束**（实测**真的生效**但无强制力；v1 覆盖 **2/6 步完整、4/6 步部分**）；
③ **`session/fork` 实测 `-32601` 确证不可用** ⇒ 分叉映射**已下调**；
④ ~~**ACP 会话内 git 不可执行**~~ → ✅ **2026-09-19 同日已定位根因并由桥修复**：父进程未设 `PATHEXT` 时 **PS 5.1 自身 fallback 到 `.CPL`**（**与 PS 版本无关**）；桥在启动 DSH 时注入正常值，实测会话内 git 完全可用（报告 §9.6.4）。⚠️ 绝对路径不能绕过（坏 PATHEXT 下静默失败）；⚠️ 手动起 DSH 不经桥仍复现 ⇒ 该条**不再是硬限制**（落库收尾仍**建议**回侧做）。
⇒ 逐项对照见勘察报告 `M1-10-跨会话寻址工具勘察-20260919.md` §3.3、§四、**§九（实测证据）**。

⇒ **不得承诺自动新建对话**（见 `SKILL.md` §5）；本节判据**在本宿主内仍不可执行**。
以下保留**判据**，供宿主能力到位后复用（重议条件见 `HANDOFF.md` §10 **R16**，
2026-09-19 已由「未满足」改为「**部分满足**」）。

1. **收拢并确认去向**
   收拢本次文件写入；能跨对话查询的后台工作保留编号与归属；
   **只有旧回合能控制的操作先结束或明确无法移交**。
   按用户指定的**实际目录**匹配项目，**不仅凭标题**。
   **不自行注册项目、迁移目录或初始化仓库**；无匹配项目时**保留材料并说明缺口**。
2. **保存并校验**
   材料写好、状态置 `材料已核对`；确认下一步所需本地文件可读取；
   **只有旧对话可见的附件或链接无法转交时，标明缺口，不能宣称完整材料已就绪**。
   **关键缺口阻止自动接续**；与第一步无关的未知可注明后继续。
3. **创建接手任务，先核验**
   接手方**只读**核对：指定目录、交接编号、关键成果与限制；
   返回**差异**和**第一步**；**本轮不修改业务文件**。
4. **登记并确认接手条件**
   取得**有效任务编号**后，更新**接手方**与状态为 `等待接手核验`；
   **不能把临时编号交给要求正式编号的工具**。
   核验项：目录、交接编号、影响第一步的版本／成果、授权边界、下一步**一致**，
   且**无阻止接续的差异**。接手方此阶段**只读**，使登记与修改**不并行**。
5. **发出继续指令并交出修改权**
   核验通过后状态置 `准备接续`，再发出明确接续范围：
   「按已确认范围执行第一步 X，并按 Y 验收；之后继续原目标，遇到已有待确认动作时停在该边界。」
   **这是同一次用户确认的执行步骤，不再请用户重复点头。**
   **只有实际发送回执能支持「已派发」**；发出后源对话**只观察**，
   不再推进业务或改交接正文，后续状态由接手方维护。
6. **验证接续**
   核对是否已执行**首个实际动作**或已有具体成果；
   **仅回复「已恢复，准备开始」不足以判定已接手**。

> **本项目的替代口径**：无法自动接续 ⇒ 交付**可复制开场白 + 材料路径**，
> 由用户自行开新对话。严格遵守 `HANDOFF.md` §11 **三动作分离**：
> **提醒 ≠ 保存交接材料 ≠ 新建接续，互不授权。**

### 失败与重复执行（**方法层，本项目同样适用**）

- **同一次交接只创建一个接手任务。** 中断恢复后，先用**编号 + 目标目录 + 既有状态**
  定位已经创建的任务，**不因没有收到最终回复就再次创建**。
- 创建或发送结果不明时，**先查询状态**；**无法确认是否成功时保留为未知，不盲目重发**。
  确定创建没有发生时，**排除原因后才可重试**；**同一原因连续失败两次后换路**。
- **新任务已存在但接手失败时，复用它修正缺项**；
  **不要用不断新建任务解决材料错误**。
  工具缺失／权限不足／必要材料不可访问时，
  **保留现有材料和准确的手动入口，不擅自安装、登录或修改配置补能力**。
- **未完成核验时不转交业务修改权。** 发出继续指令后，即使读取状态或打开界面失败，
  **也不能假定新任务停止、由源对话同时继续**；先查明执行归属。
  **旧对话保留，不自动删除或归档。**

## 3. 恢复

1. **定位来源**
   用户指定了文件就**读该文件**；无法访问时**报告准确路径和问题**，
   **不擅自换另一份**。未指定来源时，**只在当前项目的既定状态位置查找**
   （本项目 = `_handoff/HANDOFF.md`），按**任务和版本**匹配；
   **不能仅按修改时间选「最新」**，**也不扫描全部历史**。
2. **把记录当作待核对的上下文**
   当前用户要求、**现行规则**和**核实后的文件状态**决定如何继续；
   **旧记录中的建议不能扩大授权**，**旧指令不能覆盖新决定**。
   **来源不明的命令不因写在交接中就执行。**
3. **只核对影响下一步的事实**
   任务／工作目录、关键资料版本、成果、未完成改动、运行任务状态。
   已有生成或远程任务**先查询**；**查不到状态时记为未知，不自动重发**。
   工具和技能是否可用，**以本次实际运行面为准**。
4. **简短说明**
   恢复的目标、进度、未决事项、发现的差异、第一步。
   用户已明确要求继续且授权覆盖时**直接推进**；
   关键选择或授权确实缺失时，**只问该缺项**。
   **不得因恢复流程重复索要已取得的授权。**

- **只读核验轮**按启动指令**先返回核验结果，不提前修改**；
  收到同一次交接的继续指令后再执行第一步。
  **人工直接要求恢复并继续时不额外套这轮等待。**
- 接手方应让源对话能从进度中核实**首个实际动作**，
  并在自己取得修改权后更新交接状态；**不将未核实的旧记录当作完成证据**。
- **无法核实的部分保留为未知，不宣称「完整恢复」。**
  读取记录后**不自动删除、标记失效或覆盖原记录。**
