## 0. 三条不可越界（先读）

**「提醒」「保存交接材料」「新建接续」是三个独立动作，互不授权。**

| 动作 | 触发 | 不得自动扩展为 |
|---|---|---|
| **提醒** | 到检查点且当前工作已安全收拢 | 不自动保存 |
| **保存** | 用户明确要求保存 / 整理交接 | 不自动新建任务 |
| **新建接续** | 用户明确要求「新建并继续」 | —— |

- 笼统的**「交接一下」不扩展为新建任务**
- **同一次明确授权不逐步重问**（授权已含「保存 + 新建 + 核对后继续」就不拆成三次确认）
- 用户未回应时**继续已授权的工作**，不追问、不自动保存或新建任务
- **讨论、审查、修改本技能不执行交接，也不主动提醒** —— 若正好到压缩检查点，**记 `skip` 即可**

## 2. 评估：不能把沉默当作已检查

**只用已有任务事实检查；不扫描私人历史；不为评估调用额外模型。**

### 三条件（缺一不可）

| 条件 | 判断依据 |
|---|---|
| **安全位置** | 当前操作已收拢，成果、验证和运行任务归属可定位。**用户尚未验收不能写成已验收** |
| **明确后续** | 目标、范围、下一步及完成标准清楚，新对话能确定第一步 |
| **切换收益** | 本次**具体**收益（例：已结束的探索与后续执行可以分开）。**不能只说「对话太长」** |

### 何时提醒

- **首次到第 3 次自动压缩后**，安全且有后续即提醒，**不另等大阶段**
- 已有正式提醒后，再提醒须**同时**满足三条：
  1. **新实质阶段**
  2. **具体收益**
  3. 距上次正式提醒**新增至少 3 次压缩**
  - ⚠️ **同阶段改版本、调参、重渲染不算新阶段**
- **新的已核实混淆先纠正**，在安全位置可以提前提醒
- 目标或权限还不清楚时**先解决缺项，不能靠换对话绕过问题**
- **纯问答、无后续、讨论本技能 → 不提醒**
- 用户静默与指定节点按 §7 优先处理

### 结果登记（每次检查点落一条）

| 结果 | 登记 | 后续 |
|---|---|---|
| **应提醒** | `prepare`，成功后展示建议 | 成功准备**同时记录本次评估** |
| **暂不适合** | `evaluate --outcome defer` | 写明**缺项**和**下次检查时机** |
| **本轮不适用** | `evaluate --outcome skip` | 写明纯问答 / 无后续 / 讨论本技能等**实际原因** |
| 尚未安全收拢、关键缺项待解决 | `next_turn` | —— |
| 同阶段无新收益、或本轮不适用 | `next_compaction` | **在下一次真实压缩再查** |

- 其间出现**实质阶段切换或新混淆仍须主动评估**
- 用户指定节点由 `respond defer` **单独登记**；**Agent 不自行设无限暂缓**
- ⚠️ **`prepare` 被拒绝不能冒充成功评估** —— 应核实拒绝原因并登记合理的暂缓结果

## 3. 展示：最终正文最前，单独一段

本轮决定提醒、用户尚未回应时：

1. 放在**最终答复正文最前**、成果列表与任务卡**之前**，**单独一段**
2. 以 **`交接建议：`** 开头
3. 写明**具体原因 + 接续第一步 + 确认后覆盖的动作**
4. **不放进引用块、示例或代码块**，不埋在答复结尾
5. **进度消息不替代**最终展示

**例句（只作格式示范，不能据此认定项目事实）**：

> 交接建议：资料筛选已完成，后续进入方案编写，适合只带入已选资料与约束。确认后我会保存材料，在同一项目原目录新建并打开任务，核对后继续编写方案。

- **只有宿主结束事件中的最终文本通过核验才记正式提醒**，并开始冷却；
  **文本核验 ≠ 用户已经看到**
- 用户已回应、建议撤销或任务已无后续时，**不继续保留待决定建议**
- **已交付的建议不在以后每轮重贴**

2. **内容**：按 5 类取**实际存在**的内容（任务与版本 / 权威资料 / 决定与限制 /

## 7. 去重与用户回应

- 同阶段、**同一具体混淆只提醒一次**
- 后续压缩检查**可以得出「暂不提醒」**，**不能仅因冷却结束就再次催促**
- 用户明确回应「先不交接／继续做」后，**自回应时起再冷却至少 3 次压缩**；
  **重复读取同一回应不延长冷却**
- 普通工作指令里的**「继续」不自动当作回应或交接批准**
  ⚠️ **别把它读成冷却依据** —— 「用户没回应、又接着派了新活」**不等于**「用户回应了继续做」。
  正确口径（本条 2026-09-20 补充，因实测中曾据此写错登记理由）：
  **上一轮已判 `应提醒` 而用户沉默 >> 后续每轮评估一律登记 `next_compaction`**，
  理由是「**上一条建议仍待用户决定**」+「**该阶段的收益形态已提醒过**（§2 需要的是新实质阶段 + 新具体收益）」；
  同时**既不重贴建议**（§3「已交付的建议不在以后每轮重贴」）、**也不撤销**它
  （§3 撤销的前提是「用户已回应 / 任务已无后续」）。沉默既不加冷却也不消耗建议。
- 「做完 X 再提醒」以**指定节点**为准，到节点评估，**不另加次数门槛**
- **新混淆可提前评估**；同一问题去重
- **「本任务不提醒」**：关闭本任务主动提醒与自动评估补漏，**直到用户主动恢复**；
  但**显式交接请求仍执行**
