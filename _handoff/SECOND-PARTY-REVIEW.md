# 第二方复核协议（Second-Party Review）

> 建立 **2026-09-21**（对齐方案 P4；对应上游机制 **M09「专家角色 + 编排反模式」**）。
>
> **目的**：给「结论只经作者自查」这一**本项目最大的方法论缺口**补上第二方验证通道。
>
> **路径基准**：本文相对路径均相对 JVS 仓库根 `C:\Users\<user>\Desktop\JVS`。

## 0. 一句话

**作者自查不算复核。** 任何进入**交付物 / 治理文档 / 裁定记录**的**结论**，
必须由一个**独立上下文**的复核者重做一遍，并留下**可核对的留痕**。

## 1. 前置：复核通道可用性

| 通道 | 状态 | 依据 |
|---|---|---|
| `Agent` 工具（`subagent_type: Explore`） | ✅ **可用** | 2026-09-21 实测：返回成功（**非 429 / 非 400**），返回内容核对无误 |
| 历史失败记录 | ⚠️ 已缓解 | `PHASE-C-PLAN.md` 曾登记「独立子代理复核**两次均失败**（429 限流 / 额度耗尽）⇒ 结论只经作者自查」 |
| 失败排查方法 | — | 见技能 `diagnose-subagent-failure`（最常见根因 `ReasoningEffort invalid`；合法值 `low` / `medium` / `high` / `xhigh` / `none`，`max` **非法**） |

⚠️ **通道可能再次不可用** ⇒ 每次复核前先发一个**极小探针任务**确认返回。
探针失败 ⇒ **如实登记「本轮无第二方复核」**，**不得静默跳过、不得把自查写成已复核**。

## 2. 角色定义（persona）

### 2.1 复核者（reviewer）

- **职责**：在**独立上下文**中，对作者的结论做**重做式核对** —— 不是重读作者的话。
- **权限**：**只读**（对应 `Explore` 类只读子代理）。**不得修改**被复核的产物。
- **必须做**：
  1. **自己跑出原始数据**（不引用作者给的数字）；
  2. 与作者的结论**逐条对照**，不一致处**必须指出**；
  3. 给出**判据口径**（用什么命令、什么阈值、什么范围得出）。
- **不得做**：
  - ❌ 引用作者的结论作为依据（自证循环）；
  - ❌ 只做「读一遍、看起来对」的确认；
  - ❌ **再调用子代理**（见 §3）。

### 2.2 作者（author）

- **职责**：产出结论 + **可复跑入口**（命令 / 路径 / 口径）。
- **不得做**：❌ 把自己的自查写成「已复核」。

## 3. ⛔ 反模式：personas don't invoke personas

> 来源：上游 `references/orchestration-patterns.md`（M09 的另一半）。

**复核者不得再派生复核者。** 理由：

1. 每层派生都会**稀释判据** —— 第三层看不到第一层的原始数据；
2. 本项目实测过通道不稳定（429 限流 / 额度耗尽）⇒ 多层派生会**放大失败面**；
3. 「复核的复核」无限递归，**没有任何一层真正独立**。

⇒ 结论：**单层复核**。若需要更强保证，**换判据**（换一条独立的核验路径），
而不是**加一层人**。

## 4. 复核判据（怎么算「复核通过」）

| 判据 | 期望 |
|---|---|
| **独立复现** | 复核者用**自己的命令**跑出结果（不转述作者的数字） |
| **逐条对照** | 结论的**每一条**都被对照过，**不用概括句** |
| **不一致登记** | 任何不一致**必须登记**，不得写成「大致一致」 |
| **留痕** | 按 §5 格式留痕 |

## 5. 留痕格式

复核结论写进**交付物所在文档**的一个专节，或独立文件。**必须**包含：

```markdown
### 第二方复核（<日期>）

- **复核者**：<Agent / 独立上下文标识>
- **复核范围**：<逐条列出被核对的结论>
- **复核方式**：<实际跑过的命令 / 判据口径>
- **结果**：<一致 / 不一致（**逐条**列）>
- **⚠️ 复核结论本身的核对**：<见 §6>
```

## 6. ⚠️ 复核结论本身也须独立核对

**2026-09-21 实测素材**：一次第二方复核返回「`GIT-POLICY.md` 为 **569 行**」，
而 `wc -l` 实测 **568**。核对后确认：**两个小节标题逐字正确**；
行数差 1 是**口径差异**（`split('\n')` 得 569 vs `count('\n')` 得 568；该文件以 `\n` 结尾）。

⇒ 两条纪律：

1. **复核者的结论也是「一个人的结论」** —— 作者**必须核对它**，
   不能因为「来自第二方」就采信。⇒ 复核**不是单向的**：
   **作者核对复核者的结论，是流程的一部分**（这正是 `PHASE-C-PLAN.md` §六
   负向夹具 C/D 的同一精神）。
2. **口径差异与事实错误必须分开登记** ——
   「569 vs 568」是**口径**问题（无害）；若把口径差异当成「复核者错了」，
   会**误废掉一次有效复核**；反之若把事实错误当口径差异，会**放过真错**。
   ⇒ 判据：**先问「两条命令测的是同一个东西吗」**，再判对错。

## 7. 什么时候必须做第二方复核

| 场景 | 是否必须 |
|---|---|
| 结论进入**交付物 / 治理文档 / 裁定记录** | ✅ **必须** |
| 结论会**改动冻结产物 / 因果图谱 / 受限素材** | ✅ **必须** |
| 纯机械判据（门禁输出、集合差等，本身可复跑） | ⚪ 不必 |
| 只读勘察的过程性观察 | ⚪ 不必 |

## 8. 与既有机制的关系

- 本协议**不替代** `_handoff/DEFINITION-OF-DONE.md`（那是**收尾序列**）；
  本协议管的是「**结论质量**」那一层。
- 本协议**不替代**门禁 —— 门禁验**机械判据**，本协议验**判断类结论**。
- 通道排查见技能 `diagnose-subagent-failure`；
  结论落库流程见 `_handoff/DEFINITION-OF-DONE.md`。
